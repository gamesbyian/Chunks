# Chunks cohesive UX and automatic enrichment campaign (owner direction, 2026-11-05)

**Status:** binding design/interaction direction; implementation and installed-app acceptance pending. This is a coordinated UX campaign, **not** a claim of deployed behavior or a replacement for the single [WORK-QUEUE](WORK-QUEUE.md). The owner approved development use of the complete existing SVG library on 2026-11-05, with changes on request rather than per-asset visual signoff.

## Goal and authority

Restore the information architecture, visual hierarchy, restrained controls and recognizable screen purposes shown in the six [owner reference images](design/reference-images/README.md), especially the dark Transfers, Details and Storage UI concepts. Use the existing [SVG library](design/svg/README.md), [catalog](design/svg/master-inventory.json), [gallery](design/svg/gallery.html), font and Android vector generation tools as primary sources. The references are *visual and interaction direction*, not permission to invent missing backend capabilities or replace approved launcher art. Existing PRODUCT, SECURITY, storage integrity, actual transfer and scoped-operation requirements retain precedence.

**The user-facing defect:** Chunks currently places too many buttons, inputs, menus and redundant operations around every list and detail view. Fix the *screen organization*, not just colors, spacing or button polish. No feature is entitled to permanent UI merely because it exists.

## Canonical screen architecture and control placement

- **Transfers:** launch landing page; accessible compact scan-friendly list/cards across phone, remote and Combined; recognize titles and artwork when available; exact environment name/color and textual status; progress, essential rates/size/ratio; one primary Start/Pause where supported. The prominent global action is **Add torrent**. Tap opens dedicated details; keep advanced actions contextual. Avoid permanent search fields, dense per-transfer button banks and duplicate action bars. Search/filter are available on demand rather than occupying large permanent areas. Preserve mode and environment scoping and the established bottom Add/Transfers/Options affordance while reducing redundant navigation.
- **Transfer Details:** one transfer, visibly exact environment and status, its artwork/title/progress, files/peers/trackers organized into tabs or equivalent focused sections, per-transfer advanced operations in a controlled action area/menu. Never show mutually contradictory Pause/Resume simultaneously. **Identify / Change artwork** lives here and is accessible only when needed; no global art editor on Transfers.
- **Add:** one compact source + exact target/destination + Start choice screen, only conditionally showing missing inputs; optional advanced controls remain collapsed. Preserve URL/clipboard/Share, default Place versus one-time Change, authorization, error recovery and no mandatory review.
- **Options:** centralized settings, profiles/connections, privacy/authentication, artwork and metadata preferences, diagnostics and uncommon operations. Per-transfer edits never become global settings. No duplicated configuration panels on unrelated screens.
- **Storage / Workspace / Discover:** destination names and visibility must follow actual implemented capabilities and canonical PRODUCT/UX navigation, not blindly copy speculative mockup tabs. Storage summaries and cleanup only if accurate and action-capable; no deceptive quota or auto-extract promises. Empty destinations need not occupy permanent navigation.
- A single operation may have a primary home and a justified contextual shortcut; otherwise eliminate duplicate UI routes. Reuse the same state, model and scoped command even if surfaced more than once. No loss of underlying features or access for power users; progressive disclosure, searchable options and contextual actions make them discoverable.
- Keep the Pixel 6 Pro primary design target, >=48dp-class effective targets, accessible semantics, state labels beyond color, responsive text/insets/IME, TalkBack/keyboard support, reduced motion and accessible error recovery. Do not shrink controls solely to fit more.

## Automatic media metadata and artwork

**Default user experience:** after authorization for third-party enrichment, identification and artwork application are background work; users should not have to open a metadata panel during normal daily use.

1. On cold launch, session restoration and connection to *every accessible configured environment*, enumerate all visible eligible transfers needing identification, updated metadata or suitable art. Existing persisted matches/cache are reused immediately. Start the list without waiting for enrichment; run bounded, fair, cancelable background jobs across local and multiple rTorrent instances. Discover new transfers and changed identity/file evidence incrementally, including external-client additions; retry offline/transient failures with backoff. Negative results have expiry rather than permanent exclusion. Avoid duplicate network calls via shared content identity and cache; do not collapse per-transfer overrides into content-wide edits.
2. Parse names/file evidence with the existing shared lossless media identity pipeline, provider registry and privacy filters. Confident candidates apply automatically; ambiguous/weak matches remain fallback and can be corrected on demand. Do not silently label unrelated torrents as a movie. Use attractive bundled category assets for unknown content.
3. Persist resolved media identity, chosen default image, provider provenance and per-transfer manual overrides through restart, reconnection, cache cleanup and app updates. Explicit user identification, poster choice, imported image or suppression takes priority over automation. An explicit **Restore automatic** action removes the particular override; background rescans never overwrite it. The same media may share *default* identity/cache across environments, but each transfer retains its exact environment+hash scope and own override.
4. Only **Transfer Details > Identify / Change artwork** surfaces search, wrong-match correction, poster alternatives, import/custom choice and restore automatic. Show ordinary resolved art and metadata in list and details without a management workflow. Treat unresolved/offline provider failures as quiet fallbacks; do not generate global failure banners or persistent artwork controls.
5. **Options > Artwork & info** holds the app-wide automatic enrichment preference, provider/network/privacy behavior, optional cache/refresh management and category presentation. A deliberate manual refresh can be available here or contextual details; never require one as the routine launch flow.
6. **Consent/privacy boundary:** existing informed, revocable consent for outbound third-party metadata lookup remains binding. Onboarding or an appropriate one-time preference explanation should collect it clearly; thereafter permitted enrichment runs automatically, without per-transfer prompts. No external requests before consent, when disabled/locked or with protected/redacted data. Keep adult/privacy suppression, remote authentication separation, rate limiting, URL sanitization and credential/token protections. A user opting out keeps offline identification/fallbacks and cached presentation as allowed by privacy policy. Do not treat simple Add or opening details as consent.
7. Metadata enrichment must not add/start/stop/change/remove torrents, modify filenames or payloads, or perform destructive filesystem actions. Future Chunks-to-Chunks artwork sharing remains **deferred** pending its separate downstream decision gate; do not let it complicate ordinary enrichment.

## Implementation campaign and acceptance

**Phase A: evidence-based layout inventory.** Capture installed/source-rendered phone, remote-only and Combined screenshots for Transfers, details, Add, Options, connection state and meaningful Storage/Workspace routes. Inventory every button, input, action and duplicate. Compare to references by purpose and hierarchy. Produce a brief current-to-target action-placement map, identifying preserved reachable advanced paths and actual dead/duplicated UI. No large feature rewrite.

**Phase B: cohesive vertical slices.** Refactor Transfers plus Details together first, then Add and Options, followed by genuine Storage/Workspace routes. Prefer existing native Compose components and derived Android SVG vectors; avoid new independent component systems. Move or remove UI clutter, not backend capability. Each slice should ship with before/after installed screenshots and interaction tests.

**Phase C: automatic enrichment loop.** Verify existing media controller, providers, consent, caching and override policy; implement launch/reconnect/incremental scan, queue/backoff and clear per-transfer override affordance only where missing. Do not rebuild existing implemented row art, title search, poster selection or Similar Transfers. Test remote-only, local-only, Combined with 2+ real servers, app restart, third-party additions, ambiguous identification, provider offline/rate limit, lock/privacy, override persistence and opt-out zero-network-request.

**Phase D: collective qualification and release.** Test exact merged candidate head with screen-level screenshots (not only component mocks), native API29/API35 as warranted, 48dp/accessibility paths, genuine torrent lifecycles and real provider lookup where authorized. Keep CI batching and immutable source/APK provenance from CI-POLICY/BUILD; physical Pixel visual acceptance remains owner-observed and is not implied by emulator CI. A feature is not complete because its icon or screen renders; principal flows must work end-to-end.

### Measurable outcomes

- Initial Transfers shows active transfers and primary Add without having to scroll past fields/toolbars.
- A normal transfer row shows state/progress/recognizable artwork and at most one obvious per-transfer action; advanced tools remain reachable through details.
- Every transfer operation has one clear primary home, no contradictory simultaneous actions, and correct explicit environment scope.
- After prior third-party consent, a cold launch with qualifying uncached media across all available environments triggers enrichment without user navigation or taps, applies confident art, survives process restart and respects manual overrides.
- With enrichment consent off, provider network requests are **zero**, regardless of launch, Add and transfer-list viewing.
- Review before/after screenshots against reference images, with explicit notes on deliberate deviations and honest unverified physical tiers.
