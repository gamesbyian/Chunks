# Checksum-validated publication identifiers (2026-11-02)

**Status:** pure Kotlin source and tests **merged to main** in [#1071](https://github.com/gamesbyian/Chunks/pull/1071) at `a6d504fcbaa549839b9540e5ef1c2bfadb5e94ca`, from exact head `7900ee3a314c374f2965b881b46fc10b6f9486cb`. No production provider adapter, catalog lookup, external network calls or torrent/file mutations. All four source-head CI workflows passed; they are build/component and unrelated existing native Add tests, **not** installed metadata-user-journey acceptance. Tracks [#403](https://github.com/gamesbyian/Chunks/issues/403) and the [shared identity contract](../SHARED-MEDIA-IDENTITY-AND-SIMILAR-TRANSFERS.md).

A future book/serial metadata adapter can use `MediaPublicationIdentifiers` only on **exactly supplied structured identifier fields**, never regex-scraped filenames. The utility checks standard ISBN-10, ISBN-13 (978 and eligible 979) and ISSN checksums, normalizes hyphens/spaces/case, and converts verified ISBN-10 representations to their mathematically equivalent 978 ISBN-13 codes. A **979-0** code is reserved for the separate **International Standard Music Number (ISMN)** and must never become a `CheckedIsbn`, even if its GTIN-13 check digit is valid. Other checksum-valid 979 ISBNs remain supported and are **not** rewritten to invented ISBN-10s. Prefix-length contradictions, bad control digits, titles with embedded numbers, URLs, paths and obvious all-zero placeholder identifiers are rejected.

**Identity scope is deliberately limited:** ISBN usually identifies a specific publication edition/product/format, not an abstract novel; separate ISBNs can belong to different editions, formats or languages. ISSN identifies a **continuing publication/key title** and does not establish which issue or volume is present. Checksum validity is *not* proof that a real authority assigned the identifier, and neither identifier is a license to join ambiguous or conflicting provider work/entity records automatically. Source records, user corrections, provider rights and provenance remain required.

Additional standards boundary: [International ISMN Agency](https://ismn-international.org/ismn/the-ismn/) and [Library of Congress](https://www.loc.gov/ismn/about.html) both reserve **979-0** for notated-music publication identifiers. [ISO 10957:2024 example ISMN 9790345123458](https://standards.iteh.ai/catalog/standards/sist/297d2015-8b3b-4b47-a70d-e320dd5303ae/sist-iso-10957-2024) is a positive ISMN and negative ISBN test. An optional future `CheckedIsmn` must carry its own typed namespace and attribution; current code intentionally abstains rather than misclassifies it as a book. Checksum validation never proves issuance.

Primary references: [International ISBN Agency: What is an ISBN?](https://www.isbn-international.org/index.php/node/10) (13-digit prefixes 978/979, edition/format semantics, weighted 1/3 check digit), [ISBN.org standard](https://www.isbn.org/about_ISBN_standard) (10-to-13 conversion changes check digit), [Library of Congress ISSN check-digit calculation](https://www.loc.gov/issn/basics/basics-checkdigit.html) (modulus 11, 8-to-2 weights, X), and [ISSN International Centre](https://www.issn.org/faq/what-is-an-issn/) (continuing-resource/key-title semantics).

**Tests:** twelve local host Kotlin tests passed (seven original parser fixtures, three constructor/copy invariants, two ISBN-versus-ISMN negative/positive boundaries), including valid conversion `0-306-40615-2 → 9780306406157`, 979 preservation, ISBN-10 X, invalid control digits, declared-length mismatch, path/URL/text negatives, ISSN `0317-8471` and `1092-003X`, and ISBN/ISSN namespace isolation. Not a live Open Library/Crossref query, registration proof, Gradle/Android CI, or full international catalog acceptance.

**Integration:** Only after P0 and source approval, validated IDs can become a *candidate external identifier* for Open Library work/edition reconciliation; never overwrite existing user identities or infer a duplicate torrent based solely on matching text.
