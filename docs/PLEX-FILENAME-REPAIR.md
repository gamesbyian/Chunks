# Compatibility-oriented filename repair and Plex preset

**Status:** normative planned feature; not an implemented physical-rename capability. **Owner constraint:** minimally destructive edits only. This document specializes the existing three-way [rename contract](PRODUCT.md) and is governed by [SECURITY](SECURITY.md), [ARCHITECTURE](ARCHITECTURE.md), [UX](UX.md), [UNIFIED-ENVIRONMENTS](UNIFIED-ENVIRONMENTS.md) and [STORAGE-AND-EXTRACTION](STORAGE-AND-EXTRACTION.md). Execution priority and proof are maintained in [WORK-QUEUE](WORK-QUEUE.md) and [SPEC-COVERAGE](SPEC-COVERAGE.md).

## Product promise

Add **Fix for Plex** as a selectable analyzer/preset in single-file rename, bulk rename and folder scan, for files accessible through local Places and authorized remote filesystem Places, including transfer-backed files. It detects plausible media-matching liabilities and proposes **the smallest justified edits** necessary for Plex compatibility. It is not a media-title prettifier, release-name scrubber or automatic reorganizer. Future Jellyfin/Emby/Kodi analyzers may share the parser, transaction engine and preview; Plex rules/version are independent. Never claim that convention compliance guarantees actual Plex matching.

**Retention is the default:** retain every meaningful existing segment unless its removal/change is narrowly justified by a documented naming conflict. Explicitly retain resolution (720p/1080p/2160p), source (WEB-DL/BluRay/HDTV), video/audio codecs (H.264/AVC/HEVC/x265/AV1, DTS, Atmos etc.), HDR/DV, bit depth, language, release group, cut/edition and other provenance/technical tokens. Do not indiscriminately replace dots/underscores with spaces, strip bracketed segments, reorder tokens, change case or normalize a whole filename. Preserve extension exactly unless user explicitly requests a separately justified correction. Preserve user-authored names and deliberate naming conventions. Excess decoration alone is **not** evidence of a liability.

Example: `The.Matrix.1999.1080p.BluRay.x265-GROUP.mkv` may need **no change** if the Plex scanner already identifies it; do NOT automatically convert to `The Matrix (1999).mkv`. If an unambiguous year delimiter problem is established, `The.Matrix.1999.1080p.BluRay.x265-GROUP.mkv` → `The.Matrix.(1999).1080p.BluRay.x265-GROUP.mkv` is a possible minimal proposal, subject to verified applicable Plex conventions and actual filename context. A source title can be ambiguous; do not invent a year, episode, title or edition from weak inference.

## Classification and recommendation

1. Inventory names and surrounding folder topology with exact environment + Place + transfer identity/file index + backing path + source snapshot/version. Read filename facts offline first. Optional external metadata, Plex identity lookups or Plex-server inspection require separately revocable consent and sanitized queries. Plex presence/account is never a requirement.
2. Analyze narrowly scoped liabilities: ambiguous movie year/title boundaries, missing/conflicting SxxExx/episode ranges, specials/date-based series, edition labeling, ambiguous directory nesting, scanner exclusion/ignore patterns and subtitle/sidecar association. Distinguish **warning** from an actionable fix; show documented rule, evidence, confidence and target Plex library naming type. Avoid applying movie rules to television and vice versa.
3. Suggest the minimal character-span modification (insert, replace or remove) needed to remedy a proven issue. An edit includes original, proposed, exact modified spans, explanation and source evidence. Prefer zero edits if scanner-friendly already. Multiple equally plausible parses => **Needs review**, no automatic choice. Never use cosmetic cleanup as the rationale for an automatic change.
4. Present a batch review by **Safe minimal fixes**, **Needs review**, **Already compatible**, **Unsupported/unreadable**; allow per-row edits, deselection, original/proposed side-by-side, filtering and dry-run collision/permission analysis. Explicit Apply is required for any physical rename. An optional user preference can preselect deterministic proposals but may never bypass explicit execution review. A scan alone has no mutation side effects.
5. Preserve related external subtitle and sidecar discoverability, but plan companion renames separately with clear diffs and dependencies. Never rename a companion automatically by assuming stem equivalence when multiple cuts/languages/extensions collide.

## The three independent rename targets

- **Display alias / per-file Chunks label:** metadata-only and reversible; never edits original torrent metainfo, engine index, backing path or Plex-visible filesystem name. The user must see that aliases **do not repair Plex scanning**. Preserve original raw title and mapping. Existing transfer-alias workflow remains valid; file labels are distinct if implemented.
- **Engine-backed filename/path:** only if exact engine adapter + filesystem capability confirms safe coordinated mapping change, including active/incomplete transfers, atomicity/rollback and post-rename piece-hash/resume/seeding validation. rTorrent XML-RPC by itself is not proof of such support. A naive filesystem rename of actively seeded bytes is forbidden. If the readback/verification is uncertain, do not claim success or issue blind retries.
- **Independently published Plex-ready file/library path:** safely duplicate, hardlink or reflink where proven supported and explicitly authorized, preserving original torrent bytes and seeding path. Hardlinks are shared writable inodes, not snapshot copies; disallow unsafe publication of partially written torrent files. Enforce quota/space and independent provenance. Don't present this as a transfer/job Copy or Move.

When the user selects Fix for Plex from a transfer-backed file, default to **recommendations/preview**, then clearly explain available outcomes. If an in-place rename is unsafe or unsupported, offer a **Plex-ready library copy/link** only when capable; otherwise a non-mutating proposal or explicit unsupported state. Do not silently switch from physical rename to cosmetic alias or from hardlink to a large copy.

## Transaction, safety and recovery

- Batch plan IDs bind immutable snapshots of file paths, metadata, transfer membership, mapped storage root, destination, permission and relevant sidecars. Rescan and revalidate just before each operation; do not cross remote-instance/tenant boundaries. A collision, case-only rename, Unicode normalization, path length or invalid character must be resolved before execution, never silently overwritten.
- Perform an ordered, separately authorized operation with operation log, exact per-item outcomes, interruption/restart reconciliation, and conditional Undo where physically safe and identity-preserving. Don't claim general rollback across remote servers; expose partial completion and actionable recovery when atomicity is impossible.
- Existing aliases and filename-to-engine mappings have separate identities; preserve both through rename/restart/reconnect. No torrent path mutation without verified engine compatibility, no deletion of original seeding bytes, and no unexpected content re-download.
- Respect privacy lock, credential boundaries, network opt-in, remote ACL and read-only Places. No broad remote search/uploads of private paths or hashes. No destructive execution from classifier suggestions or default background organization rules.

## Acceptance cases

- Zero-change for scanner-compatible technical filenames carrying codec, resolution, source and release group; insert only justified movie-year or episode token changes, preserve other bytes exactly. Test odd dots, Unicode, multi-extension subtitles, year-looking release codes, multi-episode files, specials, editions, movie sequels, collisions and two equally plausible identities.
- Demonstrate separation: alias changes are local metadata and cannot be advertised as a Plex fix; physical backing rename is capability-gated and followed by verified torrent integrity; independent published copy preserves seeding and has accurate storage accounting.
- Local/remote/combined and two identically named files in different rTorrent instances remain isolated. Include read-only SFTP, filesystem without hardlinks, unavailable server, active write handles, incomplete transfers, case-insensitive filesystem, interrupted batch and concurrent rename.
- Unit-test deterministic minimal edit-span algorithms and abstention; fixture-test dry run/revalidation, conditional Undo and exact scope; physically test backed renames and provider quirks before claiming release acceptance. Document actual Plex version/library scanner validation separately from naming-rule conformity.

**Status boundary:** requirements and scenarios here are not proof of support on devices, seedboxes or Plex servers.
