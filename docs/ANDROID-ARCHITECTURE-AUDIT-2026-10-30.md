## Executive assessment

The existing single-module app includes functioning local libtorrent4j/native and rTorrent/XML-RPC adapters, explicit environment+infohash identities, read-only unified catalogs, typed verified/pending/uncertain outcomes, Keystore-backed credential storage, native resume/recovery work, and a substantial native/Android test rig. Keep these foundations. The dominant hazard is inconsistent **authorization and postconditions at cross-boundary mutations**: a path survey is not permanent filesystem ownership; a metadata-time magnet can transition to downloading before a file-path gate; native resume callbacks race other writes; CI can be green without witnessing intended OS/hardware conditions. Large screen-owned orchestration and an accumulation of divergent PRs amplify the risk.

**Coverage limitation:** GitHub read-only tree/file/PR/issue/CI inspection, not a full method-by-method review or runtime diagnosis. At reviewed SHA: 1,812 tracked files; 190 production Kotlin files; 193 JVM and 91 Android test Kotlin files; 59 Actions workflows; 939 docs files. Representative files and history inspected; no executable shell checkout because `git ls-remote` failed on GitHub DNS resolution. **No audit-time Gradle build, lint, device instrumentation, physical handset, protected remote-host test, credential read, performance benchmark or mutation occurred.** Historical CI (including recorded failures) must be rechecked against current candidate SHA. At inspection, main reported `protected=false`, no rulesets and zero exact-commit check runs. This is a snapshot, not evidence that other PR checks did not run. There were 38 open PRs when queried; always recheck.

Confidence **HIGH** = source-confirmed unsafe pattern or recorded controlled reproduction; **MEDIUM** = source-supported architectural/lifecycle concern requiring independent runtime characterization.

## Target architecture, alternatives and migration

Keep the **single Gradle app** for now. Preserve exact composite identity, freshness, scoped capabilities, per-backend execution and uncertain-result semantics. Introduce a narrow lifecycle-aware operation/state coordinator **inside the existing module** only after current command paths are characterized and P0 repairs accepted. UI renders immutable state and sends explicit intents; coordinator rechecks live identity, permissions, capability and observed postconditions via independent local/remote adapters. Keep read-only combined projection separate from command authority. Avoid new modules and fashionable abstractions without a demonstrated integration/test benefit. A whole-app Clean Architecture rewrite now would raise conflict/release risk while leaving unsafe native writes unresolved; pure cosmetic DTO deduplication cannot solve race safety. Future Transmission/qBittorrent and TV Compose must build on this preserved seam after G1/G2; [ANDROID-TV-AND-REMOTE-BACKENDS](ANDROID-TV-AND-REMOTE-BACKENDS.md).

## Permanent safeguards

1. **File ownership:** filename or clean point-in-time scan cannot authorize later write/deletion; use exclusive creation and creation-scoped cleanup. Treat unknown existence/symlink/path rebinding as refusal.
2. **Operation evidence:** UI visibility and RPC ACK do not confer authority or success. Reacquire exact target, observe postcondition, preserve uncertain outcome, never blindly replay.
3. **Lifecycles:** explicit long-lived state owner, cancellation, no I/O in composition, verify save/restart and native callback identity. A separate executor does not guarantee JNI returns.
4. **CI:** exact candidate SHA, genuine OS/network/byte witnesses, independent negative controls, main protection and review; never require a path-skipped check; no secrets on PRs or dynamic unapproved endpoint.
5. **Agents:** no simultaneous edits to native engine, shared navigation/model or Gradle. Inspect open fixes first. Document requirements once, proof only in ledger, active execution only in WORK-QUEUE. A green experimental reproduction may be a demonstrated **failure** rather than a safety pass.
