**Authority:** The [active work queue](WORK-QUEUE.md) ranks tasks. [SPEC-COVERAGE](SPEC-COVERAGE.md) defines product acceptance, [CI-POLICY](CI-POLICY.md) selects tests, [TEST-ARCHITECTURE](TEST-ARCHITECTURE.md) governs assertions and [NEXT-PUSH-HANDOFF](NEXT-PUSH-HANDOFF-2026-11-08.md) defines a fresh dispatch. Re-check live main, PR heads, issues, owner decisions and exact tests before acting. These are dependency cohorts, never fixed numbered agent lanes.

## Milestones and release meaning

**Daily-use Android pre-alpha:** One source-first local or authenticated rTorrent Add (file/magnet/HTTPS/Share), selected destination and Start, canonical All/device/server list, compact rows, full Details, Start/Stop/priorities, rename, session-only Remove, resume/reconnect, safe error and privacy states. APK is installable, source-exact and candid about unaccepted features.

**Android v1:** Required P0 and expressly promoted P1 features accepted on the assembled source, with real payload/peer and negative security evidence, appropriate API29/API35 and physical Pixel checks. Signing, distribution, protected-server accounts and OEM endurance remain separate evidence gates. Open P2/P3 research issues do not make the daily-use preview unfinished.

Count outcomes as **implemented, acceptance-pending, failed, blocked, accepted, deferred**. Don't infer done percent from commits, open issues or green unit tests; a percentage needs a fixed requirement denominator and evidence-weighting method. For user-visible work, report **functional** and **experience** acceptance independently under [FEATURE-EXPERIENCE-CONTRACT](FEATURE-EXPERIENCE-CONTRACT.md). Backend acceptance does not certify layout, control discoverability or human-facing state clarity.

## Speedy batch validation without false proof

For UI-impacting slices, include presentation-conformity review of actual rendered evidence, plus task interaction/semantics; record screenshots captured but uninspected as evidence-only. Do not expand full emulator fan-out merely to inspect a minor layout change.

1. Before code: name the current requirement, observable behavior, negative control, test category and which past assertion it supersedes. Keep behavioral/data-integrity/accessibility tests independent of incidental UI text or screenshots. A produced PNG is evidence inventory, not visual quality proof.
2. Per coherent slice: **one fast batch** of docs/static, affected JVM and compile checks. No expensive emulator for docs-only or each disposable integration draft.
3. For impacted platform boundaries: targeted installed API29/API35, JNI/storage, R8 or authorized disposable remote tests; keep original red and classify genuine bug versus obsolete test, fixture or environment. No retry-to-green or longer waits that hide hangs.
4. On **one reconciled candidate**: build-once and run all applicable full native verifier, foundation, R8 and real-peer/negative-control checks on the identical exact SHA/tree and verified APK bytes; rerun affected gate after changed source. No stale-head or parent-PR green is transferable.
5. Release receipts: exact SHA/tree, executed/failed/skipped count, CI runs, pulled installed APK digest/bytes, peer/piece hashes, limitations and physical-owner exclusions. RPC ACKs and screenshots alone do not prove successful BitTorrent functionality.
6. Optimize measured queue/setup/compile/emulator/diagnostic cost and duplicate fanout before reducing scope. Do not remove tests or fabricate stable required-check success.

**Daily-use stop-ship:** credential/profile/hash misdirection, bad Place/source, unapproved payload deletion or overwrites, falsely verified pieces, broken ordinary Add/Start/Stop and reproducible critical installed crashes. Optional backends, TV, widgets, advanced partfile import and font work are not automatically stop-ship.
