# Media metadata provider registry and integration feasibility (2026-11-01)

**Status:** research and implementation selection guidance, not a blanket approval to call or redistribute provider data. Normative consumer architecture: [SHARED-MEDIA-IDENTITY-AND-SIMILAR-TRANSFERS](SHARED-MEDIA-IDENTITY-AND-SIMILAR-TRANSFERS.md); existing artwork and consent rules: [TRANSFER-ARTWORK](TRANSFER-ARTWORK.md). Provider terms, quotas, uptime, coverage and field availability must be rechecked at integration time. Free API access, open data, open-source implementation, royalty-free images and permission for commercial redistribution are five different things.

## Selection principles and decision matrix

**Prefer robust, free, appropriately reusable structured *identities* and relationships to flashy cover images.** Run on-device normalization and graph queries; external APIs perform optional asynchronous enrichment. Prioritize primary provider, then category fallback, then a cross-domain linked-entity bridge such as Wikidata. Only look up entities represented in the user's authorized inventory or necessary connecting entities; no open-ended crawling. No requirement for the user to create an account to run the core torrent client; optional enrichment must degrade fully offline. Each provider adapter has its own auth/consent/legal/cost/terms/cache/breaker configuration. Credentials remain user-provided where necessary or securely delivered through a genuinely authorized mechanism; **never bake client-secret tokens into the APK** or promise an unbudgeted proxy.

## Contract for provider adapters

Adapters MUST expose `ProviderCapabilities` with: provider ID, supported categories, supported record/role types, external ID namespaces, authentication method, licensed purpose, caching/attribution/image restrictions, request cadence, concurrency and quota, safe retry status codes, and consent scope. Data fetch is **fetch/search → raw schema validation → typed observation with provenance → entity resolution → relationship assertion**. A 404, 429, 503, unsupported ID, partial result or provider downtime yields a bounded unknown/negative cache, never a false inferred relationship. Never use provider titles as global IDs. Store provider version and retrieval timestamp; preserve response fact provenance and licensing on each field/edge. Source-specific licensed content can be removed from cache without affecting independent user data. Do not combine sources in ways incompatible with share-alike or no-redistribution rules; legal/commercial decision gate before shipping each adapter.

Useful initial payload field-to-entity map (examples, not guaranteed complete across records):

| API | Field examples → canonical meaning |
| --- | --- |
| TMDB episode | `id, show_id, season_number, episode_number, crew[].id, crew[].job, guest_stars[].id` → episode, series, person, credited-for(role); namespace each ID as TMDB episode/show/person, not generic numeric ID |
| TVmaze | `show.id, episode.id, season, number, airdate`, eligible guestcrew/cast → show/episode entities and specific credits; test writer availability by endpoint |
| MusicBrainz | `id` MBID + entity type; `artist-credit`, `relations`, release-group → recording/album/artist/creator associations |
| Open Library | `key=/works/...`, `edition_key`, `author_key`, `isbn`, `cover_i` → work, edition, author and image key |
| Metron | `issue.id, series, number, credits[].creator, credits[].role, gcd_id, cv_id` → issue-level role edges and external crosswalk |
| GCD | series/issue IDs, story credits with text or linked creator IDs → candidate credit with identity quality; don't upgrade plain credit string to verified person ID |
| Wikidata | `Q...` subject/object, property predicate, qualifiers/references and external-id claims → conditional bridge evidence, not unqualified assertions |
| IGDB | `game.id, collection, franchises, involved_companies, platforms, version_parent` → game/release/franchise/contributor edges |
| Crossref/OpenAlex | DOI, ISSN, ORCID, work/author IDs, date/issue/volume → paper, publication, contributor and topic |
| F-Droid | Android application ID, signer fingerprint and index version vs repository branding/title → software edition without treating title as authority |

## Provider testing before promotion to a default

1. Fetch **real documented sample JSON** per provider and commit scrubbed, small recorded fixtures + contract tests, with record date, API version, parsed fields, missing/null shape and attribution.
2. Verify licensing for Chunks' intended distribution, commercial possibilities, visible images, local persistent cache, and any attribution/share-alike effects. Status **unknown** is not equivalent to approved.
3. Probe actual 401/403/404/429/503 behavior, expiry, pagination, ETag/Last-Modified, redirects, response size, per-IP quotas, TLS, API-key handling and Unicode/locale variation.
4. Explicitly test the cross-domain **Babylon 5 S02E07 Peter David → 1987–1998 Incredible Hulk writer-credit** route with a live episode-crew record and **multiple issue-level credits**. A manually known connection or a web page alone is not proof that a specific chosen API exposes it.
5. No installed-app acceptance or automatic networking from these research notes. Implementation starts with consent, source approvals and bounded cached reads; optional sources do not block normal torrent flows.


## Concrete cross-domain bridge: television writer to comic creator

As of 2026-11-01 the open Wikidata item https://www.wikidata.org/wiki/Q1351554 for **Peter David** publicly exposes both `TMDB person ID = 156223` (`P4985`, https://www.wikidata.org/wiki/Property:P4985) and `GCD creator ID = 10447` (`P9707`, https://www.wikidata.org/wiki/Property:P9707). This is the **specific viable link** for TV episode author identity ↔ comic issue author identity if each endpoint returns those IDs in its own credits. GCD issue #331 writer can independently be checked against https://www.marvel.com/comics/issue/9142 and https://www.comics.org/issue/42860/ . A validated Wikidata QID crosswalk is stronger than textual person-name equality, but requires collision/revision tests, reference provenance and gracefully missing property handling. The same bridge pattern can later connect MBIDs, Open Library author IDs, IMDb/TMDB people IDs and GCD/Metron creator identifiers without treating their numbering systems as interchangeable.

**TVmaze ID bridge gap (2026-11-02):** TVmaze's [*Soul Mates* page](https://www.tvmaze.com/episodes/43454/babylon-5-2x07-soul-mates) identifies [Peter David as TVmaze person **73284**](https://www.tvmaze.com/people/73284/peter-david), with the episode-specific Writer role visible on the person's credit page. TVmaze's [documented example guestcrew JSON](https://api.tvmaze.com/episodes/1/guestcrew) is an array whose fields include `person.id` and `guestCrewType` (separate Writer/Story/Teleplay/Director role types per its [official rules](https://www.tvmaze.com/faq/16/episode-extras)). Wikidata [property P11449](https://www.wikidata.org/wiki/Property:P11449) can carry a TVmaze person ID, but the current Peter David [Q1351554](https://www.wikidata.org/wiki/Q1351554) item has **no** TVmaze 73284 claim. Therefore the established TMDB↔GCD link does **not** establish TVmaze↔QID identity. Require an actual TMDB *episode-specific* credit using person 156223, or a separately verified TVmaze 73284↔Q1351554 bridge, before asserting a cross-media writer match. The exact `/episodes/43454/guestcrew` JSON remains unrecorded; neither the website nor example JSON proves its target payload.

**Anime/manga additional researched candidate:** AniList publishes a free public **GraphQL** endpoint `POST https://graphql.anilist.co` with `Media.id`, `title.romaji/english/native` and richer media structures. Its current rate-limit docs warn of **degraded 30 requests/minute** despite the nominal 90/minute limit; license, attribution, adult tagging and caching still need approval. https://docs.anilist.co/guide/introduction ; https://docs.anilist.co/guide/graphql/ ; https://docs.anilist.co/guide/rate-limiting . Do not silently enable it just because requests are public.

## Field-level real-record verification (2026-11-02)

See [dated public-record evidence and missing live JSON acceptance](research/MEDIA-API-RECORD-EVIDENCE-2026-11-02.md). TVmaze's *example* episode guestcrew JSON now confirms `guestCrewType` and `person.id`; the **specific** Babylon 5 episode writer and GCD comic story-credit API payloads remain unrecorded, and the TVmaze person ID currently has no Q1351554 bridge. GCD warns its API field format is not yet stable and a 2026 reported original/reprint credit quality issue warrants defensive attribution. Never silently promote a webpage statement into proof a selected API returns its ID/role field. Metron requires authentication; MusicBrainz release/group/recording IDs and work relationships remain separate.
