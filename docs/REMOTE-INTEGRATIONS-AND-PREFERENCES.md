# Remote integration, automation and settings portability

> **Authority:** detailed feature contract for remote connection extensions, optional outbound automation, a **secondary and deliberately limited** seedbox tools screen, and portability of Chunks preferences. User-facing guarantees are governed by [PRODUCT](PRODUCT.md), [UNIFIED-ENVIRONMENTS](UNIFIED-ENVIRONMENTS.md), [SMART-REMOTE-CONNECTION](SMART-REMOTE-CONNECTION.md) and [SECURITY](SECURITY.md). These requirements do **not** give Chunks general-purpose privileged server administration. **Status:** specification and testing goals, not evidence of shipped behavior. Inventory Fxx.yy IDs originate in [research PR #537](https://github.com/gamesbyian/Chunks/pull/537).

## Scope, exclusions and identities

This contract specifies **10** previously ambiguous items: F10.13/14/16/17; F12.08/12; F14.03/10/11/12. First-class remote support remains **rTorrent**, not a promise of heterogeneous BitTorrent daemon support. Optional integrations require separate authorization, compatible endpoints and capability verification. Everyday rTorrent monitoring/management never depends on a paid account, cloud relay, developer-operated infrastructure, media-server stack, SSH shell or companion installation.

**Profile identity** is immutable Chunks UUID plus authenticated exact server instance fingerprint, independent of editable friendly name or provider brand. **Secrets** reside in Android device-bound storage and are not exportable through ordinary settings backups. A **remote adapter** is an authenticated bounded rTorrent control transport; a **file adapter**, **media integration**, **tunnel provider** or **admin service** is a separate authority, not automatically supplied by RPC login.

## Remote setup and managed service boundaries

- **F10.13 portable remote profiles:** Offer an explicit, reviewed **Export setup** of nonsecret server profile labels, HTTPS origins/paths, selected capabilities/settings templates and Chunks presentation preferences. A separate **encrypted recovery backup** is optional only with independent owner-approved passphrase/key derivation and restore-time confirmation; never silently export Keystore secrets into plaintext or claim device-bound ciphertext restores elsewhere. Provide versioned schema, integrity/authentication, visible contents preview, exact duplicate-profile reconciliation, safe importer and opt-out from backup. Unreadable/restored secret references require fresh login. No automatic backup to third-party cloud.
- **F10.14 pairing and certificate trust:** Smart Connect may discover supported secure pairing or client-certificate routes; it cannot infer pairing support from provider marketing or bypass certificate errors. For private/self-signed CA, offer a scoped documented certificate validation/import flow bound to a particular endpoint and authenticated server identity, with fingerprint, expiry, rotation and recovery review. No persistent 'ignore SSL errors' switch, no universal trust-all, no credential forwarding to candidate hosts. Client certificates are held privately and revoked/removed on profile Forget. A QR code or deep link is untrusted input to a *review*, not automatic credential use.
- **F10.16 access through tunnels/VPN:** Permit user-configured hostnames and HTTPS proxies reachable through an existing VPN or tunnel; provide actionable disconnect, DNS, certificate, proxy-auth and split-tunnel diagnostics without silently starting server-side daemons. Built-in WireGuard/OpenVPN service management is *out of scope* unless later approved separately. The chosen connection origin and ruTorrent tenant path must never be silently changed to solve an authentication failure.
- **F10.17 remote role and privileged operations:** Distinguish multi-user/tenant read permissions, torrent write permissions, filesystem access and limited service-control rights by **current authenticated principal and exact target**, with readback probes where safe. A secondary **Server tools** screen MAY expose independently authorized, narrowly allowlisted health, quota and service status, and selected safe service start/stop/restart operations after explicit consent and supported-provider proof. Everyday Chunks controls never expose arbitrary shell/general RPC, reboot, user administration, firewall, package install/uninstall or permission escalation from rTorrent RPC. Do not reinterpret an HTTP 200 response as authorization to erase a file or proof of a restarted service.

## Secondary Seedbox tools (owner binding)

**Decision D-SEEDBOX-TOOLS-20261029.** Limited seedbox administration is approved **only as a supporting remote capability**. No administration feature is first-class navigation, competes with Add/Start/Stop/Files/Place/Collection controls or displaces primary torrent screen real estate. The canonical location is **Servers → [exact remote profile] → Server tools**. A small server-health indicator may appear in existing remote connection status, but no management dashboard, persistent admin cards, installation banner or admin-centric tab is allowed on the main Transfers list, transfer detail or Add review. In local-only mode Server tools is absent, not a dead entry. In a remote profile lacking a verified management adapter it may show a concise explanatory unavailable state without a privileged control.

### Deliberately limited actions

- **Read-only first:** show available provider/host identity, service health (running/stopped/unknown), application/version summary, storage used/free/quota, plan traffic allowance where reported, connection/authorization status and bounded resource metrics (e.g. CPU/memory/network) where supported. Differentiate provider-reported, cached and independently observed values; never imply the rTorrent XML-RPC endpoint exposes host statistics or credentials for another app.
- **Carefully gated actions:** if a separately authenticated provider API or optional narrowly scoped companion supports safe commands, offer **Start / Stop / Restart selected service** only after freshness/role/capability checks and a confirmation naming server, service, expected torrent disruption, effect on other users if known, and recovery. When control of an rTorrent service may interrupt active seeding/downloads, enumerate affected torrent jobs where available or state that the impact cannot be determined. Require an explicit per-profile opt-in to enable service controls; read-only status requires only the permissions available to that independently authorized adapter.
- **Out of scope unless explicitly approved later:** install/uninstall/upgrade arbitrary packages, host reboot, shell command execution, generic XML-RPC, user/password/role management, firewall/port-rule edits, containers/systemd unit editing, VPN installation, reverse-proxy configuration, plan/billing changes and unrestricted file-root access. Links to the provider's existing dashboard MAY open externally after clear review; no proxying user credentials or pretending Chunks executed the provider action. Remote file management already authorized by [STORAGE-AND-EXTRACTION](STORAGE-AND-EXTRACTION.md) and related file contracts remains under Files/Places, not hidden inside Server tools.
- Each profile may show none, read-only status, or specific authorized actions; never assert uniform compatibility based on seedbox brand. A successful RPC connection gives **zero presumed admin rights**. Service status and admin privilege are separately negotiated, credentials segregated, and insecure TLS or root SSH is never a shortcut.

### Secondary-screen UX and off states

**Servers → [profile] → Server tools** is an ordinary secondary page reached by opening a configured remote profile, with a back action restoring the previous torrent list/filter/scroll position. At most a low-priority text affordance appears within the profile's connection/settings screen. Transfer controls, environment switcher, destination selection, seeding rules, files and queue health keep priority for the small-screen information hierarchy. No unsolicited host metrics polling when Server tools isn't open unless a user separately enables a specific lightweight server-health refresh. Avoid long-lived foreground services or notification clutter solely for server administration.

Service actions move through **available → confirmation → submitted → reconnecting/verification → verified / uncertain / failed**, recording the exact provider operation receipt. Unknown responses require read-only reconciliation, not blind retry. Never automatically restart a server because the phone loses connectivity or the torrent speed is zero. If the adapter/auth is revoked, preserve the torrent session and show read-only unavailable. No destructive server-data action is permitted from these controls.

### Acceptance for secondary server tools

1. At 320×700, 412×892 and 200% font, Transfers/Add/Details retain their existing prime actions; no admin tab/card supplants them. One discoverable **Servers → profile → Server tools** route exists on connected remote profiles.
2. Phone-only has no remote administration prompt. A remote profile without admin capability shows an honest explanation; normal rTorrent actions continue. Two remote profiles never share administrative authority.
3. A read-only authorized provider fixture displays source and freshness for health/storage/service data; missing metrics are **unknown**, not 0 or healthy.
4. Optional service control requires explicit per-profile enablement, fresh authorization, exact service/host confirmation, affected-transfer impact and verified postcondition; timeout yields **uncertain** without blind replay.
5. Generic RPC, shell, user/firewall edits, host reboot, package deployment and hidden credential redirects remain inaccessible. UI lock, connectivity loss, restore and provider role changes revoke sensitive control surfaces.

## Separate indexer, storage and event integrations

Specialist features remain in dedicated, independently permissioned contracts: [EXISTING-SERVICE-INTEGRATIONS](EXISTING-SERVICE-INTEGRATIONS.md) governs optional Prowlarr-compatible source integration and bounded Place-based storage sync; [CROSS-SEED-AND-PAYLOAD-COPY](CROSS-SEED-AND-PAYLOAD-COPY.md) governs manual verification and actual-byte copying; [EVENT-AUTOMATION](EVENT-AUTOMATION.md) governs optional user-authored event rules, webhooks and app handoffs. They **do not** grant remote service admin rights or displace primary torrent controls. The Discovery global off switch suppresses provider discovery, but not independent local-file Add or unrelated user-authorized transfer-event rules. A user-owned persistent remote executor must be proven separately; a rTorrent login alone never supplies one.

## Optional downstream integration (opt-in, disabled by default)

- **F12.08 completion to media managers:** Offer an optional user-authorized completion handoff to an installed/routable media manager or library scanner using an individually documented adapter. Define exact event (hash-verified complete versus tracker or move status), selected environment, read-only content identity, configured destination and postcondition. Avoid exposing private tracker passkeys, names or IP addresses beyond the consented service; do not assume a Sonarr/Radarr/Plex instance exists or can access the same paths. A media-manager *import* is distinct from Chunks' Place mutation and library-copy operation; no automatic deletion of source seeding bytes.
- **F12.12 external cloud/sync/backup:** An optional connector may export a **verified independent copy** to an explicitly authorized provider/Place with space, network, quota, collision and encryption preview. Default is off, no unrequested background file upload, no server account proxy through Chunks. Preserve torrent job/backing bytes and remote seedbox quota; verify final size/hash or independently supported equivalent before claiming success. Provider-specific failures, upload retries, auth refresh and revocation are isolated from torrent lifecycle. Do not conflate backing-data migration, Chunks-only transfer-job copy and external backup.

## Personalized interface and refresh

- **F14.03 expert presentation:** Provide a consistent shared mobile-first Transfer list with optional expert columns and densities, configurable visible fields, sort/group and an accessible saved layout per environment or globally. User-selected columns are presentation-only; they cannot change engine state. At 320×700 and 200% font, prefer a selectable details sheet, horizontally scrollable expert grid or responsive stacking rather than clipped actions. Hidden sensitive fields stay hidden in locked views, recents and screenshots.
- **F14.10 refresh and background sync:** Let users choose **Adaptive (default)**, **Manual**, or a bounded interval for foreground remote polling; show last successful refresh, stale-data banner, error/backoff and actual remote environment. Polling must coalesce requests, respect server rate/capacity and avoid resubmitting mutations. Background remote monitoring is explicitly opt-in, subject to Android power/network restrictions, and may stop when the app is killed; a persistent remote daemon continues independently. Manual refresh is always available without toggling a background service. Rules that require connected enforcement show that dependency.
- **F14.11 preferences import/export:** Separate **presentation/UI preferences**, **nonsecret per-profile templates** and **sensitive credentials/tokens** in a versioned manifest. Defaults are excluded from an export if they expose sensitive transfer names/paths unless the user chooses them. Import is preview/diff/confirm with schema migration, partial failures, explicit environment remapping and stable ID collision resolution; no arbitrary settings JSON can trigger file deletion, auto-start or remote mutation. Include optional individual rule definitions only with scope remapping and safe disabled state pending capability checks.
- **F14.12 help, reports and updates:** Provide bundled offline help, version/changelog, troubleshooting and user-reviewed **Copy diagnostic summary** with privacy-safe defaults. Redact credentials, private tracker URLs, content names, paths and personal network details unless narrowly approved for that export. Crash reports/analytics are not silently uploaded. Update/install paths respect Android package ownership, chosen distribution channel and signing; do not install arbitrary downloaded APKs or promise unattended background updates. Links to project release notes may open externally, not force network use.

## UI journeys, errors and safety

**Connect:** one hostname/ruTorrent URL and credentials normally suffice; optional **Advanced connection**, **Test connection** and **Certificates** disclose exact host, profile and auth scheme. A failure keeps the draft, shows reason and offers review rather than silent target substitution. A remote profile may have a separate connected file-reader or media-manager profile with its own auth; display a small capability/authority summary for each. Disabling remote mode does not clear secrets or server state; Forget asks what local configuration to remove.

**Integrations:** Setup shows **What will be sent**, **When**, **Which phone/server**, **Which receiving service**, and **How to revoke**. User can dry-run or preview a completion event. Missing remote path mapping or content access holds/declines the action with a clear explanation. Interruption yields **queued locally / dispatched / accepted / verified / uncertain**, with an idempotency receipt per operation. A media scanner acknowledgement does not mean its library contains the media. Unverified external backup remains staged, never silently deletes source.

**Settings:** Each control displays **Applies to On phone / named remote profile(s) / Chunks-only UI**, and verified support or unsupported state. **Export my setup** begins in a nonsecret preview; **restore** never auto-connects and mutates external servers. Offline profile edits are local pending preferences until validated and explicitly applied. Use accessible names independent of color, 48dp targets, 200% font, TalkBack/keyboard and safe orientation/size acceptance.

## Capabilities, failure and persistence

Typed adapters enforce exact permissions and strong authentication; negotiated method existence is not proof of service privilege, byte visibility or action postcondition. Saving a remote host profile does not install an app, start an rTorrent daemon, create a file manager or grant SSH rights. TLS errors cannot be repaired by bypassing validation. Import/export is local, redacted, cancellable, versioned, bounded and subject to privacy lock; an exported secret-bearing backup requires independent cryptographic/security review before activation. Audit log and rules preservation are covered in [FILES-PROTOCOL-AND-DIAGNOSTICS](FILES-PROTOCOL-AND-DIAGNOSTICS.md) and [SMART-SEEDING-RULES](SMART-SEEDING-RULES.md).
