## Non-negotiable: routing and movement are job-only

**Smart Routing chooses the environment that owns a torrent job.** Any later **Move Transfer** uses existing job-only semantics: create/register on destination, verify exact target job, then separately authorize source job retirement. It **never copies, transfers, relocates, verifies or removes downloaded payload bytes**. The target starts its own download, possibly from zero. Neither Smart Routing nor manual Move offers a payload-migration feature. The unrelated, separately named existing payload Copy capability stays independent and may not be invoked by Smart Routing or Move.

The portable *job presentation and policy* associated with a transfer may accompany its metadata: display alias, artwork and identification choices, and supported rename mappings/intent. **Actual backing-file renames are not performed by moving a job**. Any target filename change requires its own supported, safe, separately authorized operation; until then preserve the requested mapping as pending/not applied, never display it as a verified physical rename. Do not alter infohash-defining metadata. No portable setting grants access to another environment's storage.

## Universal Add: source file handling

Show a **Source file handling** collapsible section when a genuine user-provided local .torrent document exists, with **Keep original**, **Archive in Chunks** (proposed default), and **Delete original**. Persist the default under Options; the individual Add can override it. For magnet and URL-only input with no original source document, hide/disable original-file actions. A fetched URL .torrent may separately offer retaining generated/received metainfo in Chunks, but it is never represented as deleting the remote original.

- **Keep:** do not alter/delete source; read only under the granted URI permission.
- **Archive:** preserve validated, exact torrent metainfo in Android app-private storage, indexed by stable torrent identity/digest and linked to relevant exact environment+hash jobs, with deduplication, atomic write + fsync/commit/verification, restart/recovery, bounded size and safe canonicalization. The archive is usable for later verified .torrent sharing and may help when rTorrent cannot provide the source metainfo. **Prefer moving** the original into Chunks private storage when Android's actual URI/provider authority permits it: first write and independently verify the private archive, then request any required original-document deletion approval and remove the original only if authorized. If source deletion fails or Android denies permission, keep the original and retain the verified private copy, explicitly reporting **Archived copy; original kept**. Never claim that an unremovable source was moved. The source file remains untouched when Add fails or has uncertain outcome. App uninstall may delete private archives; they are not permanent backups.
- **Delete:** delete the source document only *after* independently verified target Add plus proper URI authority/required user consent and exact-source revalidation. On a failed, uncertain, duplicate or interrupted Add, retain source. If deletion is refused or unavailable, preserve it and report that outcome without undoing a successfully added job.
- All file-handling operations are separate from torrent payload/files. Never delete a random source path, another app's document, remote source URL, or downloaded payload. SAF/content-provider ownership and Android deletion approval control whether deletion is possible. Do not silently delete on permission ambiguity. A confirmed archived copy may outlive source deletion.

## Per-transfer artwork/metadata exclusion

**Add > Artwork & metadata** exposes **Automatically identify and fetch artwork & metadata**, default **enabled** *for an eligible transfer*, subject to app-wide informed external-provider consent and privacy gates. Disabling stores an explicit, durable per-transfer exclusion keyed by **exact environment identity + infohash**. Excluded jobs are omitted from background discovery, scheduled retries, provider requests and auto-identification, including after restarts, reconnections and cache refreshes. Exclusion must be checked *before queuing work*, not merely used to hide a result; invalidate/cancel in-flight work safely when changed. A previous explicit artwork choice may remain locally visible as allowed by the user's privacy setting, but background enrichment does not resume without re-enabling. The same setting is editable from Transfer Details. Moving/copying a job carries the explicit preference with its other transferable presentation metadata without silently overriding an existing destination user's deliberate choice. Offline title/file-type classification for local Smart Routing remains available even when online enrichment is disabled.

## Add screen disclosure and actions

One universal Add screen with an always-reachable **Add transfer** submit action (not a compulsory review step), and collapsible sections whose expansion state may persist without remembering secrets:
1. **Source & destination**, expanded: local .torrent picker, URL/magnet and clipboard-aware text, exact environment (including Automatic / Smart Routing), destination Place/default with Change.
2. **Transfer options**: Start after Add, displayed alias versus real name, file selection/priorities only where supported.
3. **Source file handling**: Keep / Archive / Delete where an original document exists.
4. **Artwork & metadata**: per-transfer auto-identification opt-out; defaults and external consent still controlled centrally in Options.
5. **Seeding & advanced**: ratio/seed rules, bandwidth limits, tracker preferences and capability-specific controls. Advanced options never turn unsupported settings into false promises.

Source, target and Start stay immediately accessible. Keep the submit action reachable with long forms, IME and large text while preserving measured accessibility targets and Android insets. Add consent/authorization is not inferred from expanding a section.

## Smart Routing shared rules engine

**Options > Smart Routing** allows enabled/disabled policy, ordered rules, add/edit/remove/reorder, fallback and test/explain. Rules evaluate evidence available before Add (torrent file inventory, title, extensions, folder structure, trackers, labels, size, local media classification) and/or after metadata arrives. Candidate destinations include exact configured phone/remote environment identities, never environment *types* or current Transfers filter as implicit execution authority. Rules support movies, TV, books/comics, music, audiobooks, games, software, documents, pictures, archives and extensible custom classifications.

- **Order and confidence:** deterministic first highest-priority qualifying rule with declared minimum confidence; expose all competing evidence and explain selected/missing rule. Explicit user-selected environment overrides automation. Stable evidence/revision identifiers prevent nondeterministic replay. A low-confidence or ambiguous classification uses **Ask** (recommended default) or another explicitly selected fallback.
- **Privacy independence:** local classifier and rule evaluation do not require artwork network access, external provider consent or a cloud/LLM dependency. External media identity is only an optional higher-confidence input where consent and per-transfer exclusion permit.
- **Test rule:** side-effect-free preview shows matched rule, evidence, confidence, destination, missing capabilities and how fallback was reached. Safe to run against existing transfer inventory without moving anything.
- **Initial selection:** validate exact target session, capabilities, Place, saved preferences and explicit Add confirmation. If no valid environment is available, retain draft and ask rather than silently choosing an unrelated profile.
- **Magnet staging:** when supported, retrieve infohash-matched file metadata *without downloading payload*, e.g. a stopped metadata-only client session, classify and perform the **single final Add** to the selected environment. Stage must be scoped, bounded, cancelable and recoverable; avoid duplicate jobs, accidental payload start and tracker/passkey leakage. If metadata-only staging cannot be proved on a given engine, choose an explicit Ask/fallback path. Do not implement speculative cross-provider staging ahead of stable adapters.
- **Later discovery:** policy choices: **Ask before moving** (recommended default), **Automatically move job** (opt-in and only for verified, sufficiently confident exact matches), **Leave it where it is**. Subsequent classification changes are suggestions; apply move only after policy gate, stable destination identity, provenance check, bounded re-evaluation and anti-loop/cooldown. No automatic repeated oscillations. The existing separate source-retirement confirmation/authorization rules still apply; if these cannot be fulfilled without a user decision, show a pending suggestion.
- **Move transfer preferences:** carry per-job Chunks display alias, selected artwork/custom metadata, per-transfer enrichment exclusion, portable filename-renaming intents/mappings and transfer identity to destination **by default**, without falsely claiming unsupported target-file operations or replacing a preexisting destination override. A separate explicit **Carry speed and ratio/seeding rules** choice is offered on manual or automatic Move approval; default **off unless the user intentionally saves a different preference**. Preview each effective rule and whether target supports it. If unsupported, report skipped/unapplied settings, retain the original source settings until retirement is confirmed and never substitute a different rule silently. Track override provenance.
- **Remember this choice:** after a manual Move, offer to create a proposed routing rule from observed evidence and exact selected destination; show and confirm the rule conditions, order and scope before saving. A one-off move is not permission for future automatic migrations.
- **Journal:** record selected rule ID/version, evidence and confidence, destination, user override, add/readback/source retirement state, settings transfer results and any suppressed re-evaluation. Never log private tracker URLs/passkeys or user secrets. Reconcile pending/uncertain actions by read-only inspection, not blind retries.

4. **Post-Add job-only relocation** through existing Move workflow, with an approval/policy gate, anti-loop journal, preserved Chunks customizations and optional policy carryover.
5. **Existing collection reorganization preview:** run the rule evaluator across all configured observed jobs, display per-job exact-source/destination/proposed policy changes and potential re-download implications; **no moves before explicit user approval**, and never payload migration. Batch reuses identical verified job-only Move machinery.
