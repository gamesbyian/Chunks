# Shared name interpretation, media identity and Similar Transfers

**Status:** owner-approved specification, unimplemented. This contract extends [TRANSFER-ARTWORK](TRANSFER-ARTWORK.md), [PLEX-FILENAME-REPAIR](PLEX-FILENAME-REPAIR.md), [MEDIA-INSPECTION](MEDIA-INSPECTION.md), [UNIFIED-ENVIRONMENTS](UNIFIED-ENVIRONMENTS.md), and [UX](UX.md). No runtime correctness implied.

## One universal interpretation service

All consumers of transfer names, file names and media names MUST use a single versioned, deterministic shared interpretation service and typed output rather than maintaining divergent token stripping or media-identity heuristics. Consumers include artwork/metadata lookup, Similar Transfers, single Smart Rename, Bulk Rename, Plex filename repair, search/sort/grouping and duplicate review. Interpretation MUST be logically separated from actual physical rename, display aliasing, provider network access, torrent identity and filesystem path mutations.

Input: exact raw transfer/file names, extensions, containing path/collection context, file-tree hints, verified embedded metadata and available external metadata IDs. Output: preserved raw value; token spans/offsets and parsed candidates; content-type candidates; canonical display title, creator, year, season/episode/issue/volume/edition/language and technical/release fields *where supported*; confidence and ambiguity; provenance; parser/ruleset version; optional provider entity identity, IDs and source-specific confidence. Never irreversibly destroy suffixes, accents, punctuation, original scripts, editions or release metadata in the underlying representation. Store both raw and interpreted forms. Unicode-aware, locale-aware, multilingual; distinguish e.g. BTTF2 vs BTTF3, Carrie book vs television adaptation, S01E02 vs S01E03. Separately preserve strict filename/path rules.

Normalization for search and identification is **not** an instruction to rename. Smart Rename and Bulk Rename consume parsed facts and generate distinct, scoped, previewable proposals using their own presets and safety policies. Plex compatibility requires smallest justified character-span edits and retention of meaningful release tags, consistent with PLEX-FILENAME-REPAIR. Media lookup may use sanitized variants, with no raw private paths, trackers or passkeys sent to providers.

## Shared enriched media identity

Reuse the already planned category-aware, provider-independent transfer artwork/media metadata resolver in TRANSFER-ARTWORK, including existing identifier, provenance, caching, consent and rate-limit policy. Similarity must consume cached, confirmed IDs and structured relations if present, not perform a fresh outbound lookup merely because detail opens. A title collision, different adaptation or different edition must not be silently classified as identical; support related-work/franchise, same-work, same-season/show, adjacent-episode, same-edition and exact torrent identities separately. Related-work links only when provider data or strong structured evidence establishes them; avoid inferring Carrie novel-to-TV solely from title. Preserve manual overrides and expose identification correction for use by all consumers. Parser/provider changes invalidate derived indexes without modifying files.

## Expanded Details: Similar Transfers

Show an optional compact **Similar transfers** section in expanded transfer detail below essential state and controls. Default **on**; default lookup scope **all active configured environments**; option **same environment as viewed transfer**. Settings under Options > Transfer Details, not permanent primary chrome. Optional display-count limit default five with Show all. No section when no high-confidence matches. Rank same verified work/series and adjacent episodes ahead of weaker franchise connections; use specific relationship labels (Same series, Next episode, Alternate format, Same work, Also on [environment]) where supported. Use exact infohash only for duplicate torrent identity and preserve distinct environment instances. Rows link directly to exact environment+profile+transfer hash while preserving navigation state, list filters and scroll.

Reuse each environment's named user-defined palette colour in a narrow visible accent, plus **text environment name** and accessible semantics; never colour alone. Honor environment exclusion and privacy lock; stale/offline cached observations must be labelled accurately and never asserted active. "Active environments" refers to enabled/configured inventory sources and not necessarily only currently downloading transfers: seeding, queued, paused and complete transfers can be related if visible in inventory. No extra per-row RPC, no automatic remote file reads or scans for Similar Transfers. Incrementally index bounded parsed metadata from the existing canonical multi-environment transfer inventory, virtualize long lists and invalidate by source generation/identity changes.

## Tests and safeguards

- Golden multilingual/name fixtures for movies with numbered sequels, remakes, books and adaptations, anime, season/episode ranges, music album vs artist, games, software, archives, Unicode, subtitles, codec/release tokens, inconsistent separators; assert raw-preservation and parsed-span provenance.
- Cross-feature parity: identical parsed identity and source facts supplied to artwork matching, Similar Transfers, Smart Rename, Bulk Rename and Plex repair; separate each feature's action policies. Manual ID correction refreshes suggestions without touching raw names.
- Cross-environment: two exact names with distinct hashes; one hash in multiple servers; differing environment colours; one offline/locked; same-environment-only scope, filter persistence and exact-target navigation.
- Confusable titles do not create false matches; no provider-ID collision mistaken for identical content; ambiguous mappings abstain; provider API absent/offline and cache eviction degrade gracefully.
- 320×700 / 412×892, 200% text, TalkBack, keyboard and reduced motion; accessibility environment labels and controls. Performance: opening details never triggers N×M scans or additional per-transfer network RPC.
- Never rename, move, publish, remove or modify active seeding paths merely on normalization/identification; existing rename capability and transactional proof gates apply.

**Priority:** product/spec integration now, implementation behind current P0 actual .torrent/magnet Add/Start verification and durability work. Acceptance is evidence-based on installed Android and real supported remote environments.
