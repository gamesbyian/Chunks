## Agent claim / handoff contract

At the start of every session inspect *live* main, open PRs/issues, branch ownership, latest CI and this queue; if a job is already owned, take the next unclaimed independent slice. Work on a short-lived branch with focused tests and a reviewable PR. Never assert a stale workboard status after live GitHub changes. Work ahead while CI runs, but avoid runner fan-out and concurrent edits to shared code/models. Review qualified PRs; merge only with exact-head gates, independent validation appropriate to risk and no conflicting ownership. For each completed slice update the associated issue and [QUALITY-LEDGER.md](QUALITY-LEDGER.md) with exact source SHA, run/environment, observed postconditions, evidence class and unproven gaps; refresh **this queue**, not a parallel planning file. If blocked, leave a concrete cause, repro and next experiment, then advance another unclaimed job. Don't self-certify physical-device acceptance, human design approval or remote filesystem safety.

## Permanent safety and evidence invariants

Owner-authorized **development Seedhost** torrent inventory is nonconfidential and bounded exact-target destructive *torrent* testing is permitted. Credentials, embedded tracker passkeys and unrelated server inventories remain protected. This is not approval for blanket remote physical deletion, remote host shell access or speculative retry. Public test torrents originate from licensed Internet Archive/Wikimedia sources with provenance. Alias changes, library publication, remote folder metadata, backed-file mutation and cleanup are five distinct operations. Inspect [CI-POLICY.md](CI-POLICY.md) for lean required checks and the narrowly scoped disposable rTorrent adapter PR gate added in #153. Pure JVM, emulator, disposable server, development Seedhost, physical device, filesystem recovery and real-human visual review are separate evidence classes.
