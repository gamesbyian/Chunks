## Release focus and selection rule

**Immediate objective:** an independently reproducible, dependable BitTorrent client and Companion-free rTorrent remote, then a single cross-environment UI, then verified storage operations. Stabilize and maintain already-merged extras; **temporarily defer discretionary feature expansion** while P0 dependencies and acceptance remain open. This is a scheduling decision, not rejection of approved specs, a prohibition on critical fixes, or a claim that new physical-device evidence exists.

**Choose work in this order:** (1) red main / integrity / security regressions; (2) unclaimed, unblocked foundation or acceptance task in the **next executable** table; (3) parallel P0 integration or test infrastructure that cannot conflict with a claimed owner; (4) highest dependency-ready P1 storage task; (5) P2/P3 work only after prerequisite gates or explicitly approved separate capacity. If a device, secret, provider or owner approval is unavailable, record the blocker and take another unblocked **foundational** task. Never fill a hardware wait by default with an optional feature.

No new primary navigation, hosted infrastructure, unsafe file mutation or implicit remote elevation is authorized by this queue. Exact profile + infohash targeting, privacy, tracker-passkey safety, verified command postconditions, and source-data retention are non-negotiable throughout.

## Milestone gates, in product dependency order

### G0: Architecture and viability established (P0, in progress)

Shared immutable environment/transfer identity; observed-vs-requested state and safe capability semantics; deterministic read-only projection. [#571](https://github.com/gamesbyian/Chunks/pull/571) merged the pure model/catalog, [#578](https://github.com/gamesbyian/Chunks/pull/578) wired it to **All environments** and #580 added guarded Start/Stop there. The phone and server primary screens still have separate catalogs, while combined details, capability snapshots and remaining parity/acceptance are open. Existing API35/API29 emulator tests prove a limited native public-Downloads backing path (#387/#436); **preserve it**. Validate physical handset, reinstall/access loss and non-primary providers while independently settling Android service lifecycle before risky filesystem automation. Source: [ARCHITECTURE](ARCHITECTURE.md), [#567](https://github.com/gamesbyian/Chunks/issues/567), [#568](https://github.com/gamesbyian/Chunks/issues/568), [#569](https://github.com/gamesbyian/Chunks/issues/569). A model test is not real Android viability.

### G1: Ordinary torrent operation independently accepted (P0, partial)

**Remote-only functional beta:** a signed-in rTorrent profile, complete honest inventory, Add to verified parent, Start/Stop/priorities/session-only Remove, pause/reconnect/uncertain write handling and real bytes. Companion not required. Basic viable Smart Connect is a dependency; broad provider registry is not. [#1](https://github.com/gamesbyian/Chunks/issues/1), [#4](https://github.com/gamesbyian/Chunks/issues/4), [#464](https://github.com/gamesbyian/Chunks/issues/464).

**Local-only functional beta:** real licensed peer transfer and seed, independently verified file bytes, resume, storage and Android foreground/background/network/timeout behavior; no silent data loss. [#5](https://github.com/gamesbyian/Chunks/issues/5), [#568](https://github.com/gamesbyian/Chunks/issues/568), [#569](https://github.com/gamesbyian/Chunks/issues/569). Each beta can have a narrow independent acceptance record; neither automatically proves combined-mode acceptance or a production release.

**Cross-cutting:** [#9](https://github.com/gamesbyian/Chunks/issues/9) QA and [#10](https://github.com/gamesbyian/Chunks/issues/10) reproducible/signed distribution foundations must be worked on continuously. Android 10/11, modern Android 15–17, R8 and real-provider negative cases remain separate tiers. Real handset, owner visual approval and publisher signing are *unverified*, not implicit in a green PR.

### G2: One coherent Chunks experience (P0, partially implemented)

Based on G0 identity and G1 adapter contracts, migrate phone/server interfaces to one common observable transfer vocabulary, unified query/sort and scoped action presentation; support any enabled environment subset, persistent palette identity and consistent Add scopes. Never run two independent list sorts and concatenate. No extra rTorrent capabilities may be invented to force superficial parity. [UNIFIED-ENVIRONMENTS](UNIFIED-ENVIRONMENTS.md), [#567](https://github.com/gamesbyian/Chunks/issues/567), [#8](https://github.com/gamesbyian/Chunks/issues/8).

### G3: Safe storage and recovery (P1, gated by G0 storage decision + G1 reliability)

Build verified Place/file identity, ownership/permissions and read-only diagnostics first; then [snapshot export/restore #289](https://github.com/gamesbyian/Chunks/issues/289), [backing file recovery](TRANSFER-FILE-RECOVERY.md), [seed-preserving rename #7](https://github.com/gamesbyian/Chunks/issues/7), [safe remote relocation #2](https://github.com/gamesbyian/Chunks/issues/2) and [storage cleanup/extraction #70](https://github.com/gamesbyian/Chunks/issues/70) in separately accepted stages. Existing job-only Copy/Move Transfer is **not** payload migration; independent library copy and physical relocation are different operations [CROSS-ENGINE-TRANSFER-JOBS](CROSS-ENGINE-TRANSFER-JOBS.md). The optional [Companion #3](https://github.com/gamesbyian/Chunks/issues/3) is an adapter research option for proven storage authority, **not a P0 prerequisite** for ordinary remote use. No automatic payload deletion, filesystem rebind or quota enforcement without exact-byte and crash-recovery acceptance.
