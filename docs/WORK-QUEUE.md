## Evidence and safety rules

Passing Kotlin/JVM source tests establishes API-level behaviour on that runtime; emulator instrumentation establishes Android runtime interaction; actual screenshots establish rendered pixels; disposable rTorrent establishes one engine/build; owner Seedhost establishes that host; physical phone establishes a tested handset. Do not promote evidence between categories. CI must remain lean and focused (see [CI-POLICY.md](CI-POLICY.md)). Never expose secrets, credentials, private unrelated tracker URLs or raw host shell access in public PR checks.

The owner-designated development Seedhost torrent inventory can be used unredacted for **nonsecret** fixture names, paths and visual QA, and targeted destructive torrent tests are permitted under reviewed safeguards. Other accounts, passwords, cookies, passkeys and unrelated FTP files are not covered. No automatic cleanup, file deletion, move or archive extraction from classifier suggestions. Preserve seeding originals by default.
