## Fixed-signature Robolectric runtime dependency failure diagnosis (2026-11-03)

**Actual red Actions evidence:** In [UX #1194 Android foundation 41670063830](https://github.com/gamesbyian/Chunks/actions/runs/41670063830), JDK/Gradle compiled the debug sources and executed **1,478 JVM tests; one failed**, namely `AuthenticatedTransfersFooterTest`. Its originating test exception reported **`MavenArtifactFetcher.java:130`** followed by **`java.net.SocketException`**, before the test could certify UI behavior. The official [Robolectric maintainer CI explanation](https://robolectric.org/blog/2023/11/11/improving-android-all-downloading/) confirms that Android framework JARs are downloaded by Robolectric's separate runtime `MavenArtifactFetcher`, not Gradle's dependency resolver. [Robolectric's documented configuration](https://robolectric.org/configuring/) has independent SDK JAR repository/offline settings. The observed stack establishes a runtime dependency network-fetch **symptom**, but not the precise socket/network/root cause; do not falsely claim a specific HTTP 429 or assert the UX is correct. The original red remains a genuine incomplete acceptance result, not a pass.

**Non-mutating optimization:** The already-required, read-only `tools/ci_failure_digest.py` now detects **only** the exact conjunction of static markers `MavenArtifactFetcher` and `java.net.SocketException` within bounded text of a failing JUnit test, **only for the `android-jvm` suite**. It emits `diagnostic_hint=possible-robolectric-runtime-dependency-network-fetch` with a fixed recommendation to investigate runtime SDK JAR availability. This hint **never changes** the original `phase=test_assertion`, failing case identity, source SHA, JUnit counts, artifact content, exit status, or green gate; it does not automatically retry, skip or pass anything. Unknown failures and foreign suites remain unclassified. The diagnostic does **not serialize raw stack traces, exception messages, URLs or secrets**, and offline adversarial controls explicitly check privacy and fail-closed results. The first failure remains visible and its original JUnit retained.

**Alternative deferred:** Explicit Robolectric `android-all-instrumented` prefetch/offline caching could remove runtime network dependence, but would introduce a large SDK JAR transfer, new classpath/cache semantics and platform-version upkeep. No measured warm/cold timings, exact artifact size or parity test yet justify promoting that topology change; keep it as a targeted future experiment rather than weakening the current 1,400-plus JVM tests or adding unconditional retry cost. If an agent requalifies a red foundation build, preserve the failed attempt's evidence and run affected tests at the current exact head. This diagnostic change adds no runner, Android emulator, or real rTorrent/BitTorrent job.

## Verified Robolectric API35 SDK preflight experiment (2026-11-03)

**Exact evidence, no guesswork:** In [foundation run 41670063830](https://github.com/gamesbyian/Chunks/actions/runs/41670063830) (9.42 runner-minutes), the uploaded original JUnit XML from `jvm-fatal-error-reports` records `AuthenticatedTransfersFooterTest.classMethod` failing in Robolectric's `MavenArtifactFetcher` while retrieving `org.robolectric:android-all-instrumented:15-robolectric-13954326-i7`; nested cause is `java.net.SocketException: Connection reset` during `ByteStreams.copy`. In [run 41673906594](https://github.com/gamesbyian/Chunks/actions/runs/41673906594) (14.90 runner-minutes), `CombinedAddAndFreshnessTest.classMethod` failed while fetching **the same exact version**, with SHA-512 **POM mismatch** inside the Maven fetcher. These two runs represent **24.32 observed runner-minutes** ending without a complete accepted JVM result, not 24.32 minutes of proven savings. Both original failure receipts remained red and are not user-feature regressions; unrelated genuine Compose assertions and JVM native aborts remain separate.

**Narrow hypothesis and reversible implementation:** Upstream Robolectric 4.17's `MavenArtifactFetcher` returns immediately if its expected JAR exists under `~/.m2/repository`, and validates both JAR and POM against published SHA-512 sidecars when fetching. `tools/prefetch_robolectric_sdk.py` uses that **existing native cache layout** without changing Robolectric's implementation: with the explicitly checked Robolectric 4.17 pin, retrieve only the pinned Android 15 (API35) `15-robolectric-13954326-i7` JAR and POM from Maven Central over HTTPS using streamed size bounds, checksum both against the published SHA-512s, validate Maven coordinates and the JAR ZIP/class content, then move them into the local Maven cache with the JAR installed **last**. Failed/reset, truncated or mismatched downloads retry the affected object at most **three** times, with bounded exponential delays and a **240-second total CI step ceiling**. On exhaustion the foundation job remains **red before Gradle compilation**. Existing checksum-matched local files can be reused; unverified or corrupt cache entries cannot be silently accepted. Logs contain only fixed operation/status/counts, not raw external content, credentials or runtime test output.

**Scope and acceptance:** The preflight runs once at the start of the existing Android foundation job, on its already-selected PR changes. All `:app:testDebugUnitTest :app:assembleDebug`, JVM forks, exact source/provenance, fail-closed original JUnit and physical APK preflights remain intact; **no** `--tests` filter, `robolectric.offline`, SDK blanket selection, new workflow, persistent cache/artifact, new emulator or protected host access. Other SDK versions continue to use Robolectric's ordinary resolver rather than being falsely treated as locally supplied. Documentation validation runs synthetic negative controls for a reset connection, tampered SHA-512/POM/JAR, corrupt existing cache, forbidden version and SDK, unsafe URL or oversize, and verifier ordering. The standalone tests contain no actual download. Only the existing foundation check may establish that the new early prefetch really succeeds in GitHub Actions. Track elapsed preflight and exact all-attempt runner consumption against historical ~6-minute green foundation runs. **A roughly 191 MB fresh download can increase wall time on healthy runs.** Keep or revert the experiment based on observed failure reduction *and* net aggregate runner/feedback cost; do not claim a speedup just because a network failure moves earlier.

**Sources:** [Robolectric's CI dependency-fetch recommendations](https://robolectric.org/blog/2023/11/11/improving-android-all-downloading/), [Robolectric 4.17 resolver API](https://robolectric.org/javadoc/4.17/org/robolectric/plugins/LegacyDependencyResolver.html), and the original Actions JUnit receipts above. Historical [Robolectric issue #11345](https://github.com/robolectric/robolectric/issues/11345) was already fixed before stable 4.17; do **not** mislabel these reset/checksum failures as its Conscrypt/XDH regression.

## Long-running PR cost reports: complete pagination and bounded calendar scope (2026-11-03)

**Verified usability defect:** Prior to this change, `tools/ci_runner_cost_report.py` refused to analyze any branch with more than 100 Actions runs, while directing the operator to narrow the date window without providing any `--created` argument. That blocked complete long-lived PR and main-branch investigations. GitHub's documented REST APIs support `page`/`per_page` for both workflow runs and all-attempt jobs, and `created` filtering for runs ([workflow runs](https://docs.github.com/en/rest/actions/workflow-runs), [jobs](https://docs.github.com/en/rest/actions/workflow-jobs)). A read-only live query with `branch=ux/73-wave2-phone-first-and-footer-20261103&created=2026-11-03..2026-11-03` returned **54 run records**, confirming the date selector actually works; this query **did not allocate a CI runner**. Earlier main-push research had already retrieved **202 records over three pages** for October 27–November 2, well beyond the previous script's 100-run limit. These facts demonstrate reachability, not measured runner-minute savings.

**Implemented reporting interface:** `python3 tools/ci_runner_cost_report.py --repo gamesbyian/Chunks --branch YOUR_BRANCH --created 2026-11-01..2026-11-03` requests complete 100-item pages of workflow runs, and complete `filter=all` job pages for each run. There are no additional requests for runs/jobs whose first page is already complete. It validates real, forward-ordered calendar dates, rejects malformed API counts/pages/identities, changing page counts, duplicate IDs, and results beyond GitHub's **1,000-run filtered-search ceiling** rather than producing a misleading subtotal. For a still-active source scope it refuses before requesting N job pages, preserving the existing completed-only accounting contract. The selected calendar window is **inclusive**, and the result is explicitly **window-scoped**, never the unqualified lifetime total for a branch. Pagination is not an atomic snapshot if GitHub changes the matching runs between page reads; run on a settled branch or stable historical window, and investigate any reported mismatch. No workflow, device acceptance, GitHub concurrency policy or source-based correctness gate is altered.

**Offline controls:** Multi-page 101-run and 101-job/all-attempt test fixtures; full cardinality, exact IDs and known runner-time totals; changing/partial/duplicated pages; more-than-1,000 truncation refusal; invalid/reversed date range; early refusal on live in-progress runs. This extends the already accepted source-revision, cancellation, retry and step-level measurement infrastructure rather than creating another analytics subsystem. Do **not** infer a benefit from the extra API requests if a branch is short; the improvement is accurate availability of evidence on larger histories.

## Read-only, exact-head PR receipt checker (integration QA)

`tools/check_pr_exact_head.py` verifies GitHub Actions records for a **specified full PR head SHA**, optional exact base SHA, and explicitly named workflow/check contexts. It double-reads the PR refs to reject head/base movement during inspection; rejects missing, cancelled, skipped or failed required contexts and workflow runs belonging to another PR; and returns nonzero on incomplete/unavailable evidence. It is a **review helper**, not branch protection, an Actions job, proof that the test exercised the promised scenario, or authority to merge. It does not start workflows or access protected testing hosts.

Workflow names are exact and must be selected from the change's actual path-triggered gate policy; optional/manual/secret-bearing workflows are not blanket requirements. Use the named SHA to prevent stale evidence, review the actual patches/test logs, and continue recording emulator versus handset/host evidence separately in [QUALITY-LEDGER](QUALITY-LEDGER.md). ## Strict post-Stop foreign-byte acceptance receipt (independent QA)

`tools/require_post_stop_nonclobber.py JUNIT_XML` is a **manual acceptance filter** for the real native `LocalNativePostAddCollisionProbeTest.stoppedPartialJobThenForeignSkippedFileAndRestartCharacterizesNativeWrites` report. ## Opt-in dataSync timeout repro (#569, 2026-10-29)

`android-fgs-timeout-repro.yml` runs one class, `LocalEngineServiceTimeoutInstrumentedTest`, through `tools/fgs_timeout_repro.sh` on a disposable API35 emulator.
- **Setup:** it applies Android's documented test controls (`am compat enable FGS_INTRODUCE_TIME_LIMITS`, `device_config … data_sync_fgs_timeout_duration 15000`) and restores both on exit.
- **Triggers:** manual dispatch, plus PRs that touch the service timeout files, the test, the script or the workflow. It is not an app-wide fan-out.
- **Skipping:** the ordinary native suite skips the class through an instrumentation-argument assumption. The script fails if the test was skipped or did not report one pass.
- **Scope of evidence:** a pass proves shortened-limit handling on that emulator only. It does not cover the six-hour budget, Doze, OEM killers or handsets.
- **Sudden process death:** the same job then runs `tools/process_death_repro.sh` (`LocalEngineProcessDeathInstrumentedTest`).
  - **Phase A** seeds under the service and SIGKILLs its own process.
  - **Phase B**, in a new process, must find no leftover ongoing notification, the transfer restored stopped, unchanged bytes and a 100% recheck.
  - **Failure conditions:** the script fails unless phase A armed and actually died, and phase B passed without being skipped.
- **Device reboot:** `tools/reboot_repro.sh` (`LocalEngineRebootInstrumentedTest`) seeds under the service, then runs `adb reboot`.
  - After boot it requires that no Chunks process started by itself, and that there is no engine and no ongoing notification.
  - On opening the saved state, the transfer must restore **stopped** with unchanged bytes.

## Manual real-peer lifecycle modes (#568/#569)

`android-public-swarm.yml` is manual-only, needs no secrets and uses the sanitized Debian netinst. It has these exclusive modes:
- **default:** download a verified budget;
- `interrupt`: SIGKILL mid-download, then check restore and continuation;
- `doze`: forced deep idle during a foreground download;
- `netflap`: Wi-Fi and data off for 30 s, then require recovery.

A peer shortfall is reported as INCONCLUSIVE, never as engine acceptance. Each run is emulator evidence only.

## Targeted escalation (manual first)

- XML-RPC parser and transport changes: deterministic fixture and fuzz/size/error cases, plus a bounded integration matrix when justified.
- Server state mutations and idempotence: synthetic test service and disposable rTorrent host; verify real acknowledgement and no duplicate actions on response loss.
- Filesystem changes: independent fault injection using disposable datasets, multiple volumes and process kills at each journal checkpoint. Fail closed if recovery cannot be proved.
- Android UI changes: occasional targeted emulator screenshot/hierarchy atlas and real handset walkthrough, not a permanent broad screenshot job.
- Local engine background: device tests across Android background/service types and network conditions; do not use one green assembly to infer reliability.

## False-positive safeguards: physical installation and reboot

The physical Android APK preflight (`tools/physical_android_preflight.sh`) must pin one selected non-emulator ADB device, exhaust the `dumpsys package` output without `grep -m1`/SIGPIPE, reject missing or conflicting version identities, require explicit package-manager `Success` and an exact-activity launch receipt. Its fake-ADB regression is an offline negative control, **never** evidence of physical handset installation or publisher signing.

The opt-in `tools/reboot_repro.sh` must record a syntactically valid kernel `/proc/sys/kernel/random/boot_id` before phase A and require a **different** valid boot ID plus Android boot-complete before phase B. `sys.boot_completed=1` alone does not prove reboot. A mock-ADB suite rejects unchanged and invalid identities before any expensive emulator phase.
