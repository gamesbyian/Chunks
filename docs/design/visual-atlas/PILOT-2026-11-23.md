## Crucial exclusions / next implementation steps

1. **Fixture ≠ full app.** Some isolated native Compose test hosts use light test surfaces unlike Chunks' actual dark application shell; every image must be reclassified against test source and the real route. White-background fixtures must not be passed off as a dark-mode in-app screen. In particular P10/P11 (`combined-detail-identity-412-200pct.png` and `combined-detail-place-412-200pct.png`) come from `CombinedDetailIdentityInstrumentedTest`, which renders `CombinedTransfersScreen` in a constrained standalone host (`requiredSize(412.dp, 892.dp)`, forced 200% text) and does not supply `onConnections`. Consequently its three-item embedded footer **cannot be used as evidence that the real `MainActivity` four-root footer is missing**. The production root supplies `onConnections`; functional tests must verify that assembled route independently.
2. **No real long screenshot.** Neither fixture heights nor cropped dialogs constitute a genuine tall scroll capture. Implement a deterministic scroll-and-stitch or honest tall-host technique preserving native geometry, with raw frames and seam verification.
3. **Atlas still not delivered.** The full 10–20 final images with route/component inventory, component variants, UI audit worksheet, stable contact sheet/manifest, reproduction mechanism and approved-source comparison remain open. The current 17 samples demonstrate availability of genuine render evidence, not completeness.
4. **Functional acceptance separate.** No image demonstrates successful transfer Add/Start, real Seedhost behavior, mobile document grants, TalkBack, device integrity or release readiness. Shard 1's failed test remains red in historical evidence even after a later passing rerun.
5. **Reproduce:** check out source `c96f64d1c7828a511e328a9119060d3b9b54c7c4`; use the exact linked GitHub Action run's named artifacts and the inventory above. Preserve original bytes and SHA metadata; do not manufacture tall screens or silently recolor screenshots.
