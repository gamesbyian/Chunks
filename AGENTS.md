# Chunks agent operating instructions

**Dispatch model:** Chunks has **no fixed agent roster, numbers or permanent lanes**. The owner dispatches one or several agents as needed, and each agent works on exactly the current instruction, including across all technical areas when directed. Read [dispatch and concurrency coordination](docs/AGENT-LANES.md) solely for live overlap/serialization principles; old Agent 1–5 allocations are historical, never restrictions or default assignments. Review live source, open PRs and checks before deciding what work remains. A broad dispatch may implement, test, document and integrate across areas; qualify claims against real source/executed evidence and use independent review when required.

**Execute current instructions, do not narrate progress here.** [WORK-QUEUE](docs/WORK-QUEUE.md) ranks what to do; [AGENT-LANES](docs/AGENT-LANES.md) defines dispatch-based concurrency coordination; [NEXT-PUSH-HANDOFF](docs/NEXT-PUSH-HANDOFF-2026-11-08.md) supplies the step-by-step startup; [SPEC-COVERAGE](docs/SPEC-COVERAGE.md) holds gates, and [QUALITY-LEDGER](docs/QUALITY-LEDGER.md) holds evidence. Previous rolling checkpoints are preserved in [AGENTS-HISTORY-2026-11-09.md](AGENTS-HISTORY-2026-11-09.md).

## Owner mandate: actual transfers outrank simulated success (2026-11-01)

For **every BitTorrent feature implementation, review and acceptance**, apply [REAL-TRANSFER-ACCEPTANCE](docs/REAL-TRANSFER-ACCEPTANCE.md): real .torrent files, resolvable magnets, actual rTorrent/libtorrent servers, real peers/piece-verified bytes and production installed-app paths are the **primary acceptance evidence**. Mocks, artificial hashes, test doubles and simulated responses are secondary iteration/negative-test tools, never grounds to say ordinary Add/Start/download/seed works. A green component suite or engine `active` bit without actual peer/piece progression does not close a user journey. State exact proof tier and remaining owner-device limitations.

Before adding a custom implementation for an ordinary operation, **inspect upstream libtorrent/rTorrent semantics and reference-client behavior (ruTorrent/Transdroid)**. Reuse established mechanisms by default; require a demonstrated unsupported need and review before building bespoke protocol, disk, state or lifecycle machinery. Keep real positive paths and independently seeded/rTorrent hosted evidence ahead of elaborate mock-only hardening. Do not auto-mutate a protected host from PR CI; use specifically authorized scoped/manual gates.

## Proportional requirements and ordinary client behavior

Before turning a hypothetical hazard into a universal release blocker, apply the [requirements-rationality audit](docs/REQUIREMENTS-RATIONALITY-AUDIT-2026-10-31.md) and the operation's conventional-client contract. State the observed defect, user-authorized operation, affected capability/provider/OS, smallest adequate mitigation, positive-path acceptance and separate unverified evidence tiers. Do not replace existing safeguards with speculation or let an invented invariant force a bespoke storage backend where documented platform/library semantics suffice. Keep real data-loss, path escape, accidental deletion, stale/ambiguous remote mutation and credential errors blocked until corrected. ## Binding product and command invariants

- **One experience, explicit scopes:** local-only (default offer), remote-only and combined local/multiple-rTorrent-profile configurations share navigation, Transfers lists, details, Add, controls and settings semantics. Environment identity, exact settings scope and destructive target must remain obvious. Switching environment is non-mutating; disabling a mode does not delete jobs/files or forget credentials. [UNIFIED-ENVIRONMENTS](docs/UNIFIED-ENVIRONMENTS.md).
- **Transfer jobs vs files:** Copy Transfer and Move Transfer move/copy *torrent job registrations only*, including batches. Destination downloads independently. Move removes only the source **job** after verified target Add and a separately confirmed source retirement; all original files remain. Distinct labelled payload copy, independent library publication, backing-file relocation/rename, archive extraction and deletion have different operations and permissions. [CROSS-ENGINE-TRANSFER-JOBS](docs/CROSS-ENGINE-TRANSFER-JOBS.md).
- **Stable identity:** transfer = exact engine/server profile + verified infohash; Place = actual accessible storage root, permissions and provider; Collection = semantic many-to-many group. Chunks display alias, original torrent name, real backing file mapping and detached published copy are independent. Do not infer ownership from a shared path or torrent title.
- **Observe before claiming success:** distinguish requested, acknowledged, verified, refused and uncertain; a timeout is uncertain and requires read-only reconciliation, never blind mutation retries. Enforce fresh target identity, permissions, capability and observed postconditions. rTorrent `d.erase` is session removal, not an authorization to delete payload bytes.
- **Capability boundaries:** rTorrent/rakshasa libTorrent differs from phone Arvid libtorrent4j. Authenticate remote RPC with verified transport and bounded tenant scope. Never silently downgrade HTTPS or connect to a different numbered ruTorrent instance; provider catalog entries are hints, not compatibility proof. The optional Companion is not required for everyday remote control. [SMART-REMOTE-CONNECTION](docs/SMART-REMOTE-CONNECTION.md) and [rTorrent matrix](docs/RTORRENT-COMPATIBILITY-MATRIX.md).
- **Destinations:** Add shows verified per-environment default Place with optional Change/recent locations; no forced picker. The phone's intended default is a verified `Downloads/Chunks Downloads` under Android's standard user-visible Downloads, independent of Chrome's private preferences. Remote uses its own server default and never creates a Chunks-branded folder. A setting or RPC acknowledgement cannot prove physical file movement.
- **Protect content and consent:** no destructive cleanup or automatic deletion of seeding files, including source archives after extraction. Storage caps can be advisory; only proved execution can enforce quotas. Auto-extraction defaults off; user-visible organization and title suggestions cannot silently mutate paths, downloads or labels. External metadata enrichment requires informed revocable consent. [STORAGE-AND-EXTRACTION](docs/STORAGE-AND-EXTRACTION.md), [TRANSFER-ARTWORK](docs/TRANSFER-ARTWORK.md), [TRANSFER-PRIVACY-LOCK](docs/TRANSFER-PRIVACY-LOCK.md).
- **Android accessibility and evidence:** 48dp-class controls, 200% fonts, TalkBack/keyboard, high-contrast redundant status, reduced-motion alternatives and truthful pending/offline/error UI are required. Emulator/JVM or a screenshot is not physical phone, Android service/Doze, vendor SAF or human visual acceptance.

- **Audit closure and architecture safety:** [2026-10-30 Android architecture audit](docs/ANDROID-ARCHITECTURE-AUDIT-2026-10-30.md) records AUD-01–15, linked existing PRs, required tests and limits. [#687](https://github.com/gamesbyian/Chunks/issues/687) is tracking only; [WORK-QUEUE](docs/WORK-QUEUE.md) controls actual G0–G5 priority. Resolve native existing-file, ownership-blind copy/probe and protected-secret hazards before broad refactors. **Exclusive creation and ownership-scoped cleanup** remain required for internal metadata, non-replacing new-object publication and automatic rollback; explicit user-reviewed file replacement follows [USER-DIRECTED-FILE-OPERATIONS](docs/USER-DIRECTED-FILE-OPERATIONS.md) with target-specific consent and without unowned cleanup; ordinary native BitTorrent payloads in an explicitly chosen Place follow [D-LOCAL-COLLISIONS-20261031](docs/DECISIONS.md) and may recheck/reuse/replace exact same-name regular files. A clean survey never grants path escape, unrelated writes or arbitrary cleanup. Never add Compose-time disk/network effects; test process-state restoration and exact-head negative controls. Do not close audit findings for unmerged code or stale CI.

## Development/test boundaries

- **Protected Seedhost:** the primary development instance retains its existing scoped authorization. **Owner update (2026-11-03):** agents may populate the already configured second and third rTorrent instances with identifiable torrent/magnet fixtures for combined mode or any other feature, including bounded exact-job mutations required by the test. Verify each numbered HTTPS route, credentials and target independently; restrict data deletion to authorized exact disposable test fixtures with actual file-level verification. Do not touch unrelated pre-existing transfers, arbitrary remote files or other accounts, and never auto-run protected writes on PR/push. The complete authorization and boundaries are in [SEEDHOST-REMOTE-TESTING](docs/SEEDHOST-REMOTE-TESTING.md) and [D-SECONDARY-RTORRENT-TEST-FIXTURES-20261103](docs/DECISIONS.md). Protect passwords, cookies and RPC tokens, and never print tracker announce URLs or passkeys in CI output. **Owner exception (2026-11-02):** The owner permits personally selected private `.torrent` metainfo in this repository for testing and explicitly accepts any private-tracker passkeys in those files; do not delete, block or escalate those test fixtures merely for that reason. This does not authorize access to unrelated private accounts or automatic private-tracker/server operations in PR CI. Incoming BitTorrent peer ports are separate from HTTPS RPC ports. Use licensed [public fixtures](docs/PUBLIC-TORRENT-FIXTURES.md) for untrusted/public CI Add/peer tests.
- **Visual source:** immutable owner PNG reference sheets remain in [reference-images](docs/design/reference-images/README.md); independent SVG variants are registered in [the asset production plan](docs/design/reference-images/SVG-ASSET-PRODUCTION-PLAN.md). The transparent [approved app icon SVG](docs/design/approved/chunks-app-icon-master.svg) is canonical; generate the Android VectorDrawable with `node tools/generate_launcher_vector.cjs` and verify with `node tools/generate_launcher_vector.cjs --check` and `gradle verifyChunksLauncherArtwork`. Do not replace it with PNG or unapproved variants. SVG work uses `python3 tools/validate_svg_library.py` and `python3 tools/check_svg_approved_derivatives.py`.
- **P0 magnet APK gate:** do not request owner installation as a diagnostic. First qualify two independently sourced public magnets through the actual installed app, real rTorrent/libtorrent metadata and verified pieces, production Stop/Start/Remove, resumed bytes, truthful peerless UI and exact-hash cleanup. Bind the offered APK digest and source SHA to that positive run. Preserve already passing `.torrent` evidence and separate emulator, live-server and physical/OEM claims. See [REAL-TRANSFER-ACCEPTANCE](docs/REAL-TRANSFER-ACCEPTANCE.md).
- **APK provenance:** public debug/preview/release artifact filenames must contain `chunks`, with an updated SHA-256 receipt; an internal `app-debug.apk` remains an intermediate only. A debug build is not publisher-signed release proof. See [BUILD](docs/BUILD.md).
- **Typeface isolation:** all ongoing font creation occurs only on persistent `font/lab` with local builds and **no routine font PRs/Actions**. Promote one meaningful reviewed batch after source/optical tests; never touch font work from an app agent. The [font-lab contract](docs/design/CHUNKS-FONT-LAB-OPERATIONS.md) overrides ordinary feature-PR cadence in that lane.
- **Test design:** follow [TEST-ARCHITECTURE](docs/TEST-ARCHITECTURE.md). Locate controls by the stable ids in `ChunksSemantics`, assert outcomes and verified state rather than screens or copy (copy only where wording is the requirement), and treat screenshots as evidence unless an approved baseline exists. When a deliberate UX change breaks a test, identify the requirement, re-express it against the new UI and record the mapping; never delete, weaken or skip an assertion to turn CI green. Draft PRs skip the heavy gates and skipped is not passed: run `python3 tools/pr_acceptance_report.py --sha <exact head> --profile integration` before integrating, and keep `tools/native_atlas_manifest.json` classified.
- **Documentation discipline:** one canonical feature contract, concise cross-references, explicit supersession and status/evidence separation. Run `python3 tools/check_docs.py` and `python3 -m unittest discover -s tests -p 'test_docs_check.py'` after docs edits; both are offline and should not fan out Android/font CI. Never copy a session log into the active queue. A preserved historical snapshot exists at [archive](docs/archive/AGENTS-2026-10-29-preconsolidation.md), but it is not an active instruction source.
