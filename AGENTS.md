# Chunks: permanent agent operating contract

**Mission:** Build Chunks into a colourful, deeply usable **Android-native BitTorrent client and first-class rTorrent remote**, with intuitive Places, independent Collections, clean optional display aliases and safe control of seeding data. No functionality is considered delivered merely because it is written into a specification.

**Transfer privacy feature:** Before changing the protected transfer screens, Android authentication, credential persistence or notification visibility, consult [docs/TRANSFER-PRIVACY-LOCK.md](docs/TRANSFER-PRIVACY-LOCK.md). Keep its planned status distinct from verified functionality.

**Add location contract (2026-10-27):** The destination picker must be visible but optional. Resolve a valid local/remote default automatically; local target is Downloads/Chunks Downloads only when Android storage and engine writes are verified; remote uses its existing configured default and creates no Chunks folder. Surface per-scope validated recent destinations. Consult the product, UX, architecture and work-queue documents; do not treat historical mandatory-picker language as current intent.

**Approved Android downloads approach:** Use Android's standard shared Downloads location as the preferred local Chunks Downloads parent, not an attempted lookup of Chrome's private download preference. Let users select and remember another verified location, including SD cards when supported. Public folder claims require real libtorrent write/resume/seed capability acceptance. Keep remote-server folder behavior unchanged. See PRODUCT, ARCHITECTURE, UX and WORK-QUEUE.

**Transfer detail requirements (2026-10-27):** Read PRODUCT, UX, ARCHITECTURE, SECURITY, STORAGE-AND-EXTRACTION and WORK-QUEUE before changing local↔remote Copy/Move or archive deletion. Never confuse magnet/metainfo handoff with copied bytes, or successful extraction with permission to delete torrent-backed archives; exact verified destination and seeding consequences are release gates.

**Owner reference-variant policy (2026-10-27):** Six source PNG sheets in `docs/design/reference-images/` remain immutable. Preserve **every** inconsistent reference concept as a named independent SVG variant, rather than picking one silently. The authoritative [asset index](docs/design/svg/master-inventory.json) distinguishes independent vector drafts, approved master, planned fidelity work and true aliases to identical existing art; the [production plan](docs/design/reference-images/SVG-ASSET-PRODUCTION-PLAN.md) stays beside the PNGs. New visual assets must be self-contained vectors, registered in the index and searchable [gallery](docs/design/svg/gallery.html); run `python3 tools/validate_svg_library.py` and `python3 tools/check_svg_approved_derivatives.py`, plus the renderer atlas workflow. Experimental launcher variants must never replace the canonical approved Android foreground without explicit approval.

**Approved app icon invariant (owner, updated 2026-10-27):** The canonical, editable transparent illustration is `docs/design/approved/chunks-app-icon-master.svg` (no black rounded-square bezel). The unchanged original `docs/design/approved/chunks-app-icon-master.png` is **reference-only**, Git blob `03a8677e9c90f4b455e67683fcc4a2b79517b1ea`. Android cannot package raw SVG directly as an adaptive launcher foreground, so `node tools/generate_launcher_vector.cjs` deterministically converts the SVG into `app/src/main/res/drawable/chunks_launcher_artwork.xml`, a native Android VectorDrawable with gradients. Both normal and Preview builds use this XML through `@mipmap/ic_launcher`. **Never** reinstate a runtime launcher PNG, embed the PNG inside an SVG, restore the obsolete seven-block icon, or create a second independently edited launcher image. Run `node tools/generate_launcher_vector.cjs --check` and Gradle `verifyChunksLauncherArtwork` before publishing. Changes originate in the SVG and regenerate its vector derivative; PNG remains a historical reference.

**APK filename invariant:** Every downloadable Android APK in CI artifacts and GitHub Releases must include `chunks` in the filename (`chunks-debug.apk` for the normal app and `chunks-preview.apk` for side-by-side builds). Gradle's internal `app-debug.apk` is allowed only as an intermediate. Regenerate paired SHA-256 receipts after renaming, and keep physical-device preflight filename checks and docs in sync.

**Batch transfer requirement (2026-10-27):** Local ↔ remote Copy/Move must support multi-select batches as well as individual details. Reuse per-transfer integrity and explicit source-deletion gates; retain scope-aware selection, per-item destination/conflict checks and durable partial-failure recovery. Consult PRODUCT, UX, ARCHITECTURE, SECURITY and WORK-QUEUE before implementing.

## Product invariants

- Transfer identity = engine/server scope plus verified infohash; **Place** = actual accessible storage root and privileges; **Collection** = semantic many-to-many grouping. Original torrent name, Chunks-only display alias, file mapping, derived independent library copy and approved destination suggestion are separately represented.
- A user optionally choosing a different Place at Add selects the actual **parent destination** for local or remote engine; otherwise use the valid environment default. A string setter, preview or acknowledged RPC is not a verified physical move. Refuse unsupported operations or offer a safe deferred move or independent library copy; never invent one-click portability across SAF/providers or managed remote hosts.
- A display alias edits **only** Chunks metadata. A source-only name suggestion must remain an editable proposal; don't infer celebrity guest, episode title or show identity absent from source. No auto-rename, auto-delete, implicit organization move or transfer-side effect from a suggestion.
- `d.erase` is **session-only** and must not be conflated with deleting payload. Backing-file rename, relocate, copy and cleanup require independent capability, fresh exact-object target, shared-reference checks, journal/recovery and verified seeding postcondition. Keep original source for library copies and archive extraction.
- XML-RPC via authenticated TLS is the direct rTorrent baseline; optional Companion is **not** required for everyday remote control. rTorrent/rakshasa libTorrent is different from the phone's Arvid libtorrent4j. Capability-check individual builds, auth proxies, views, methods, integer encodings and filesystem providers rather than version guessing.
- Distinguish requested, attempted, acknowledged, verified, uncertain, refused and post-failure recovery. **Never blindly retry a remote mutation after a missing acknowledgement**. Refresh is observation, not proof no concurrent actor modified server state.
- Optional local storage caps are independent of remote storage; warnings do not enforce quota. No automatic removal of files needed for sharing, not even extracted source archives. Auto-extraction off by default; do not equate the merged bounded manual ZIP-to-SAF path with arbitrary archives or device acceptance.
- No guaranteed Android background uptime, unrestricted filesystem, real physical handset UX or cross-provider SAF success without device proof. Validate API-level FGS policies, process death, grants, net changes and battery limitations.
- Primary interactions must include 48dp-class targets, 200% text, TalkBack/keyboard and gesture alternatives, reduced-motion and status distinctions. Bright personality must not hide destructive results, warning text or error recovery.

The owner also permits **destructive torrent testing on that development instance**, limited to reviewed exact-hash single-target Adds, lifecycle/priorities, Remove and appropriately proven mutation paths with preflight, independent verification and recovery. It is **not** authorization to expose credentials, cookies, passkeys or tokens, mutate unrelated hosts/accounts, use arbitrary shell, or remove backing files without the separately gated ownership and crash-safety proof. See [SEEDHOST-REMOTE-TESTING](docs/SEEDHOST-REMOTE-TESTING.md). Public Add fixtures: licensed [Internet Archive/Wikimedia corpus](docs/PUBLIC-TORRENT-FIXTURES.md); never random tracker URLs.
