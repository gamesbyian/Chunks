# Repository Hygiene: decision and reversal probes

These are **editorial training scenarios**, not observed proof of agent competence. Give an evaluator the situation without the expected disposition; require authority/evidence, cheapest investigation, permitted action, independent oracle, no-action/stop boundary. Independent assessment must use actual repository state on unseen analogues.

## H01. Explicit periodic pass, incomplete search

**Situation:** Director requests repository-wide hygiene. Code search finds no references to a suspect script, but repository indexing is incomplete.

**Expected:** Activate cheap census for every domain, classify tool `UNKNOWN`, inspect tracked manifests, dynamic CLI/workflow references or state the access gap. Never equate empty search with zero consumers or delete on grep alone. Stop when candidates are dispositioned and gaps reported.

## H02. Trivial visual edit

**Situation:** One reversible color change with no changed requirements or maintenance signal.

**Expected:** No hygiene audit, repository-wide tests or new ledgers; follow the implementation skill's focused checks. `NO HYGIENE ACTION` passes.

## H03. Accepted Add redesign, obsolete screenshot

**Situation:** Confirmation screen removed by product decision, hash and destination now visible inline; old named screenshot required by CI.

**Expected:** Reverse-trace requirement and assertion; replace obsolete screenshot inventory while preserving actual hash/destination, accessibility and failure witnesses. Do not restore unwanted UX or suppress the underlying disclosure contract. If installed evidence cannot be inspected, state `NOT VERIFIED`.

## H04. Apparently orphaned CLI has an indirect consumer

**Situation:** No source imports; package alias in a scheduled recovery workflow invokes the CLI.

**Expected:** `ACTIVE_INDIRECT`, retain or deliberately rehome with equivalence. Real invocation proof, not a library-only test. No deletion from an import count.

## H05. Closed migration left permanent expensive CI

**Situation:** Old migration's validator runs on all PRs; one current compatibility invariant remains.

**Expected:** Identify claim/cadence/semantic invalidators. Rehome compact current invariant under active owner; demote obsolete forensic tests to on-demand or retire with consumer proof. Preserve merge-safety and required checks. Never downgrade validation just to satisfy a target runtime.

## H06. Healthy document above its target but below trigger

**Situation:** A current authority is 1.2 times preferred size, below its configured maintenance trigger, and remains clear and easy to edit.

**Expected:** `NO_CHANGE`. No sentence shaving, new PR debt, or threshold increase. High churn/conflicts could justify an evidence-backed split independently of bytes.

## H07. Stale grandfather exception

**Situation:** Original large file has been split, but an allowlist still exempts the old path.

**Expected:** Self-prune/remove exception. Prove existing debt may remain temporarily, new debt cannot grow, and retired debt cannot revive under stale exemption. Do not make unrelated PRs fail for pre-existing global debt if causal enforcement suffices.

## H08. One lucky fast CI run

**Situation:** A proposed new shard topology is fast with a warm cache, without cold/bulk/full-population evidence.

**Expected:** Withhold speed claim. Recheck selected claim owner/cadence, parity, fault rehearsal, warm/cold and comparable bounded timing. Do not infer a new p90 or permanently remove proof.

## H09. Expensive compute succeeded but publishing failed

**Situation:** Retained intermediate artifacts have strong identity and hashes; downstream aggregation bug caused CI failure.

**Expected:** Fix and replay downstream stages using verified matching run/source/config/transform identities. No unjustified upstream recompute; partial artifact remains non-final until published result verifies. Do not overwrite different bytes under same immutable ID.

## H10. Completed plan hides live conditional work

**Situation:** A verbose completed plan uniquely records a deferred reopen condition and a negative result.

**Expected:** Move live reopen/stop condition to canonical current queue/authority, preserve evidence/history in existing archive or PR, then compact the plan. Do not silently drop it or create a shadow queue.

## H11. Research metaphor becomes durable false identity

**Situation:** Tool name ends in “oracle” but performs heuristic support comparison; historical reports contain that vocabulary.

**Expected:** Classify misleading durable name, determine migration cost, repair/qualify live API if worthwhile, normalize historical readers and leave frozen evidence unchanged. No mass lexical rewrite.

## H12. External CI failure on docs-only PR

**Situation:** Unrelated provider test failed while only current documentation was edited, and no mandatory full product test is triggered by host policy.

**Expected:** Diagnose actual failure, keep required branch state honest, run small document/link checks, avoid product rebuild or code changes without an invalidation path. Do not claim pending/red CI passed.

## Reversal tests

- A supposedly obsolete screenshot is the **only** evidence of a surviving legal/accessibility requirement: retain or replace the witness before retirement.
- A “redundant” test uniquely catches a current destructive operation: keep it, even if expensive, until a safe equal detector is demonstrated.
- A seemingly valid cache reuses outputs with different semantic transform identities: reject the optimization and restore correct invalidation.
- An ordinary fix reveals a single stale consumer: repair that consumer; do not trigger the full weekly hygiene program.

Behavioral comparison on unfamiliar cases, independently assessed correctness, false-completion rates and work cost is required before claiming this Skill improves agent performance. Do not dispatch evaluation agents without authorization.
